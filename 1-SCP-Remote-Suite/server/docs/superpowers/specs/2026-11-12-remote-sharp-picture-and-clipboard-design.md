# สเปก: ภาพรีโมตคมชัด และ copy/วางแบบ VNC (งาน A และ B)

วันที่ 12 พฤศจิกายน 2569 · ลำดับงานทั้งหมดคือ A → B → C → D → E เอกสารนี้ครอบคลุม A และ B เท่านั้น งาน C (ความลื่น/ต่อใหม่อัตโนมัติ), D (ตัวติดตั้งและอัปเดตโปรแกรม), E (ผลเครื่องมือช่างบนเซิร์ฟเวอร์ และใบแจ้งซ่อมเชื่อมรีโมต) จะมีสเปกของตัวเอง

## เป้าหมาย

ผู้ดูแลแจ้งว่าการรีโมต "ขัด ๆ" ภาพบางครั้งเบลอจนแทบอ่านไม่ออก และ copy/วางไม่สะดวกเหมือน VNC งานนี้ทำให้

1. ตัวอักษรบนจอรีโมตคมเท่าจอจริงเป็นค่าเริ่มต้น ทั้งในเว็บและในโปรแกรม SCP-Remote
2. คัดลอกข้อความแล้ววางข้ามเครื่องได้ทันทีโดยไม่ต้องกดปุ่มส่ง/รับ
3. Ctrl+C / Ctrl+V ไฟล์ในโปรแกรม SCP-Remote ผ่านการทดสอบกับเครื่องจริง และเอกสารไม่ขัดกัน

## สิ่งที่พบในโค้ดปัจจุบัน

| เรื่อง | ที่อยู่ | สภาพ |
| --- | --- | --- |
| การจัดขนาดภาพ | `deskAdjust()` ใน `views/default.handlebars` และ `views/sharing.handlebars` | โหมดเริ่มต้น (0) ยืดหรือย่อภาพให้เต็มหน้าต่างเสมอ จอเครื่องลูกที่เล็กกว่าหน้าต่างจึงถูก **ขยาย** และมัว โหมด 1:1 (1) ไม่คิดอัตราขยายจอของ Windows (125–150%) จึงยังถูกขยายอยู่ |
| การเข้ารหัสภาพ | `desktopsettings` ในสอง view, บันได `profiles` ใน `public/scripts/scp-session.js` (สำเนาที่ `hospital/desktop-app/session-health.js`), `hospital/desktop-app/main.js` | ทุกจุดใช้ WEBP คุณภาพ 100 ซึ่งยังเป็นการบีบอัดแบบเสียรายละเอียด ขั้นต่ำสุดของบันไดย่อภาพเหลือ 75% |
| ตัวเลือกคุณภาพในโปรแกรม | `main.js` บรรทัดที่ครอบ `SendCompressionLevel` | ถูกตรึงเป็น `(4,100,1024,50)` ตัวเลือกคุณภาพในแถบสถานะจึงไม่มีผลในโปรแกรม |
| คลิปบอร์ดข้อความ (เว็บ) | `desktopsettings.autoclipboard` | ค่าเริ่มต้น `false` ต้องกดปุ่มเอง |
| คลิปบอร์ดในโปรแกรม | `inject-clipboard.js`, `clipboard-transfer.js`, `clipboard/` | มี Ctrl+C/Ctrl+V ทั้งข้อความและไฟล์แล้ว ยังไม่เคยทดสอบระหว่างสองเครื่องจริง `DESKTOP-APP.md` ยังเขียนว่าทำไม่ได้ ขัดกับ `CLIPBOARD.md` |

ข้อจำกัดของการวิเคราะห์: สาเหตุข้างต้นมาจากการอ่านโค้ด ยังไม่ได้ยืนยันด้วยตาบนจอจริง การรับงานจึงต้องให้ผู้ดูแลลองกับเครื่องจริง

## งาน A — ภาพคมชัด

### A1 จัดขนาดภาพแบบไม่ขยาย

เพิ่มไฟล์ `public/scripts/scp-remote-fit.js` มีฟังก์ชันล้วน

```
fitSize(deskW, deskH, parentW, parentH, dpr) → { width, height, scale }
```

- `width/height` เป็นขนาด CSS ของ canvas, `scale` คืออัตราส่วนพิกเซลเครื่องลูกต่อพิกเซลจริงของจอช่าง
- ถ้าภาพที่ 1 พิกเซลต่อ 1 พิกเซลจริง (`deskW/dpr` × `deskH/dpr`) ใส่ในพื้นที่ได้ ใช้ขนาดนั้นและจัดกึ่งกลาง — **ไม่ขยายเกิน 1:1**
- ถ้าใส่ไม่ได้ ย่อลงให้พอดีโดยคงสัดส่วน (พฤติกรรมเดิม)
- ปัดขนาดเป็นจำนวนเต็มพิกเซลจริง เพื่อไม่ให้ขอบพิกเซลเหลื่อม

การต่อเข้าระบบ: ไฟล์นี้ครอบ `deskAdjust` แบบเดียวกับที่ `scp-remote-ui.js` ทำอยู่ ทำงานเฉพาะโหมด 0 (พอดีจอ) และแก้โหมด 1 (1:1) ให้หารด้วย `dpr` ด้วย โหมด 2 (ยืดเต็ม) คงเดิม การซูมด้วยสองนิ้วบนมือถือใน `scp-remote-ui.js` ต้องยังทำงานบนขนาดที่ได้จาก `fitSize`

โหลดในสามที่: `views/default.handlebars`, `views/sharing.handlebars` และฉีดจาก `main.js` ของโปรแกรม (ไฟล์เดียวกัน ไม่ทำสำเนา) การแก้ view ต้องมีคอมเมนต์ `SCP-Remote:` และจดลง `UPSTREAM-CHANGES.md`

ตำแหน่งเมาส์ไม่ต้องแก้ เพราะคำนวณจากสัดส่วนขนาด canvas ต่อขนาดที่แสดงอยู่แล้ว (โหมดพอดีจอเดิมก็ย่อภาพ) แต่ต้องมีเทสต์ยืนยันว่าคลิกตรงจุดเมื่อภาพถูกจัดกึ่งกลาง

### A2 ระดับ "คมชัดสูงสุด" แบบไม่เสียรายละเอียด

บันไดใหม่ใน `scp-session.js` (และสำเนาในโปรแกรม)

| ระดับ | ค่า `SendCompressionLevel` | หมายเหตุ |
| --- | --- | --- |
| คมชัดสูงสุด (ค่าเริ่มต้น) | `[2,100,1024,50]` PNG | ไม่เสียรายละเอียด กินแบนด์วิดท์มากที่สุด |
| คมชัด | `[4,100,1024,50]` WEBP 100 | ค่าเริ่มต้นเดิม |
| สมดุล | `[4,70,1024,100]` | เดิม |
| ประหยัดเน็ต | `[4,45,1024,200]` | **ไม่ย่อภาพแล้ว** (เดิม 768) ลดแค่คุณภาพและอัตราส่ง |

- ตัวเลือกที่ช่างเลือกจะถูกจำไว้ใน `localStorage` (`scpQualityChoice`) ครั้งถัดไปเปิดด้วยค่านั้น ถ้าไม่เคยเลือกใช้ "คมชัดสูงสุด"
- "ปรับภาพอัตโนมัติ" เริ่มที่ระดับบนสุดและไต่ลงตามเกณฑ์ RTT/คิวค้างเดิม
- ค่าตั้งต้นในสาม view/โปรแกรมต้องตรงกับขั้นแรกของบันได: `agentencoding: 2`
- `main.js`: เลิกตรึง `SendCompressionLevel` ให้ตัวเลือกมีผลในโปรแกรม ปุ่ม HQ ส่งค่าระดับบนสุด และเลิกบังคับ `select.value="0"` ทับค่าที่จำไว้

**การตัดสินใจที่กลับจากเดิม:** เมื่อ 23 ก.ย. เลือก WEBP แทน PNG เพื่อประหยัดแบนด์วิดท์ และมีเทสต์ตรึงไว้ใน `hospital/tests/session-health.test.js` ผู้ดูแลเห็นชอบเมื่อ 12 พ.ย. ให้ PNG เป็นค่าเริ่มต้นเพราะภาพเบลอ เทสต์ชุดนั้นจะถูกแก้ให้ตรึงการตัดสินใจใหม่: ขั้นแรกคือ PNG, ขั้นที่เหลือคือ WEBP, ไม่มีขั้นไหนย่อภาพ และสามจุดตั้งค่าต้องตรงกัน บันทึกเหตุผลใน `WORK-IN-PROGRESS.md`

### การทดสอบงาน A

- เทสต์หน่วยของ `fitSize`: จอเล็กกว่าหน้าต่าง (ไม่ขยาย), จอใหญ่กว่า (ย่อพอดี), `dpr` 1 / 1.25 / 1.5, สัดส่วนแนวตั้ง, ค่าศูนย์หรือค่าที่ไม่ใช่ตัวเลข
- เทสต์บันได: ลำดับและค่าตามตาราง, ไม่มีขั้นที่ scaling ต่ำกว่า 1024, สำเนาโปรแกรมตรงกับเว็บทุกไบต์ (เทสต์เดิม), ค่าตั้งต้นสามจุดตรงกับขั้นแรก
- เทสต์ว่า `main.js` ไม่ครอบ `SendCompressionLevel` ด้วยค่าตายตัวอีก
- ตรวจในเบราว์เซอร์ด้วยหน้าทดสอบที่มี canvas ลายตารางหมากรุก 1 พิกเซล: ที่ `dpr` 1 และ 1.25 ภาพต้องไม่มัว และพิกัดคลิกตรง
- **รับงานโดยผู้ดูแล:** รีโมตเครื่องจริงหนึ่งเครื่องผ่านเว็บและหนึ่งเครื่องผ่านโปรแกรม ดูตัวอักษรไทยในโปรแกรมโรงพยาบาล และอ่านค่า KB/s ในแถบสถานะเทียบระดับ "คมชัดสูงสุด" กับ "คมชัด"

## งาน B — copy/วางแบบ VNC

### B1 ข้อความอัตโนมัติสองทางในเว็บ

- ค่าเริ่มต้น `desktopsettings.autoclipboard = true` ใน `views/default.handlebars`
- การย้ายค่าครั้งเดียวต่อเบราว์เซอร์ (คีย์ `scpAutoClipboard1` แบบเดียวกับการย้ายค่าคุณภาพที่มีอยู่): เปิดให้ผู้ที่มีค่าเก่าบันทึกไว้ หลังจากนั้นถ้าช่างปิดเองในหน้า Settings ให้คงค่าที่เลือก
- กลไกส่ง/รับคือของ MeshCentral เดิม (อ่านคลิปบอร์ดทุกวินาทีระหว่างเซสชันควบคุม) ไม่เขียนใหม่ เบราว์เซอร์จะถามสิทธิ์อ่านคลิปบอร์ดครั้งแรก ถ้าปฏิเสธ ปุ่มส่ง/รับด้วยมือยังใช้ได้เหมือนเดิม
- ทำงานเฉพาะเซสชันที่ควบคุมเครื่องได้ (ผ่านการขออนุญาตแล้ว) ไม่ทำงานในโหมดดูอย่างเดียว ต้องมีเทสต์ตรึงข้อนี้

**ผลด้านความเป็นส่วนตัว (ผู้ดูแลรับทราบแล้ว):** ข้อความที่คัดลอกบนเครื่องลูกระหว่างรีโมตจะมาที่คลิปบอร์ดเครื่องช่างทันที รวมข้อมูลผู้ป่วยถ้ามีการคัดลอก เพิ่มหนึ่งย่อหน้าใน `HANDOVER.md` หัวข้อความเป็นส่วนตัว

### B2 ไฟล์และข้อความในโปรแกรม SCP-Remote

โค้ดมีอยู่แล้ว งานคือทำให้เชื่อถือได้

- แก้ `DESKTOP-APP.md` ที่เขียนว่า copy/paste ไฟล์ทำไม่ได้ ให้ชี้ไป `CLIPBOARD.md`
- ทำใบทดสอบภาคสนาม `hospital/desktop-app/CLIPBOARD-FIELD-TEST.md`: ข้อความไทย/อังกฤษสองทาง, ไฟล์เดียว, หลายไฟล์, โฟลเดอร์, ชื่อไฟล์ไทย, ไฟล์ 100 MB, กดปฏิเสธคำขออนุญาต, ยกเลิกกลางทาง
- ข้อที่ไม่ผ่านในการทดสอบจริง แก้ทีละข้อด้วยขั้นตอนหาสาเหตุ (เทสต์ที่ล้มก่อน แล้วจึงแก้) ไม่เดาแก้ล่วงหน้า

### การทดสอบงาน B

- เทสต์ว่าค่าเริ่มต้นและการย้ายค่า `autoclipboard` อยู่ครบ และการปิดด้วยมือไม่ถูกเปิดกลับ
- เทสต์ว่าคลิปบอร์ดอัตโนมัติผูกกับสิทธิ์ควบคุม ไม่ทำงานในเซสชันดูอย่างเดียว
- `hospital/tests/viewonly.test.js` และชุดเทสต์คลิปบอร์ดเดิมต้องผ่านโดยไม่แก้
- **รับงานโดยผู้ดูแล:** ทำตามใบทดสอบภาคสนามกับเครื่องจริงสองเครื่อง

## ขอบเขตที่ไม่ทำในงานนี้

- ไม่เปลี่ยนโปรโตคอลภาพเป็น VNC/RFB จริง ยังใช้ช่อง KVM ของเอเจนต์เดิม
- ไม่เพิ่ม copy/paste ไฟล์ด้วยคลิปบอร์ดในเว็บเบราว์เซอร์ (เบราว์เซอร์ไม่ให้อ่านไฟล์จากคลิปบอร์ดของ Explorer) เว็บยังใช้ลากไฟล์และแท็บไฟล์
- ไม่เปิด `desktopMultiplex`
- ไม่แก้เอเจนต์ที่คอมไพล์แล้ว

## การนำขึ้นใช้งาน

- งาน A และ B1 เป็นไฟล์หน้าเว็บ: `npm run build:hospital` แล้วเพิ่มเลข `?v=` ไม่ต้องรีสตาร์ตบริการ
- ส่วนของโปรแกรม (A ใน `main.js`, สำเนา `session-health.js`): ต้อง `npm run package` แล้วแจกโฟลเดอร์ใหม่ จนกว่างาน D จะมีตัวอัปเดตอัตโนมัติ
- ทุกขั้นต้องผ่าน `npm run test:hospital`, `npm run check:hospital`, `npm run check:config`
- ในโฟลเดอร์งานมีการแก้ที่ยังไม่ commit จากงานก่อน (ฟอร์มพิมพ์ใบแจ้งซ่อม, CSS แดชบอร์ด, `views/default.handlebars`) งานนี้ทำต่อบนนั้น และ commit แยกเฉพาะไฟล์ของงานนี้เมื่อผู้ดูแลสั่ง

## ย้อนกลับ

- ภาพ: เลือก "คมชัด" (WEBP) ในแถบสถานะได้ทันทีรายคน หรือเปลี่ยนลำดับบันไดกลับ
- จัดขนาด: เอา `scp-remote-fit.js` ออกจาก view แล้ว build ใหม่ `deskAdjust` เดิมยังอยู่ครบ
- คลิปบอร์ด: ปิดในหน้า Settings รายคน หรือเปลี่ยนค่าเริ่มต้นกลับเป็น `false`
