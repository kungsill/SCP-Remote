# อัปเดตทั้งระบบด้วยคำสั่งเดียว

`npm run update:system` — คำสั่งควบคุมเองสำหรับอัปเดต SCP-Remote ทั้งระบบในครั้งเดียว: build หน้าเว็บใหม่ → รีสตาร์ต server แบบปลอดภัย → ยืนยันว่ากลับมาแล้ว → รายงานผล

## ทำไมคำสั่งเดียวถึง "push ไปทุกเครื่องลูก"

การรีสตาร์ต server **1 ครั้ง = ตัดการเชื่อมต่อเครื่องลูกทุกเครื่องชั่วคราว** พอแต่ละเครื่องต่อกลับ มันจะ**เทียบ core (และ binary ถ้าเปิด auto-update) ที่ตัวเองมีกับของ server แล้วดึงตัวใหม่เอง** — เท่ากับ push อัปเดตไปทั้งฟลีตพร้อมกัน โดยไม่ต้องรอรอบ auto ปกติ

## วิธีใช้

```
npm run update:system            # อัปเดตจริง (จะถามยืนยันก่อนรีสตาร์ต)
npm run update:system -- --check # ดูสถานะ + สิ่งที่จะทำ โดยไม่เปลี่ยนอะไร
npm run update:system -- --no-build   # ข้าม build หน้าเว็บ (แค่รีสตาร์ต + push)
npm run update:system -- --yes        # ไม่ต้องถามยืนยัน
```

## ทำอะไรบ้าง (ตามลำดับ)

1. **build หน้าเว็บ** (`build:hospital`) — สร้างหน้าไทย/อังกฤษใหม่จาก template
2. **รีสตาร์ตแบบ orphan-aware** — หยุดบริการ → ตรวจว่า process เก่าตายจริง + พอร์ต 8443 ว่าง (ถ้ามี orphan ค้างจะฆ่าให้ ลูกก่อนแม่) → **`Start-Service` ตรงๆ** (ไม่ใช้ `service:start` ที่เคยรายงานว่าสำเร็จทั้งที่ไม่ขึ้น) → รอจนพอร์ต listen + HTTPS ตอบ 200
3. **รายงาน** — PID เปลี่ยนไหม, HTTP กี่, เครื่องลูกต่อกลับกี่เครื่อง

ถ้า build ล้มเหลว **จะไม่รีสตาร์ต** (กันปล่อยของพัง) ถ้าพอร์ตไม่ว่างหลังเคลียร์ orphan ก็หยุดเพื่อความปลอดภัย

## core vs binary

- **core (JS)** — push ทุกครั้งที่รีสตาร์ต ไม่ว่า auto-update จะเปิดหรือปิด
- **binary (.exe เนทีฟ)** — push ก็ต่อเมื่อ **agent auto-update เปิด** (คือ `settings.noagentupdate` ไม่ได้ตั้งเป็น true) คำสั่งจะแสดงสถานะนี้ให้เห็นก่อน

> ถ้าตั้ง `noagentupdate: true` ไว้ (เช่นตอนทดสอบ preview agent) คำสั่งจะ push แค่ core — เอา setting นั้นออกแล้วรีสตาร์ตถึงจะ push binary ด้วย

## ข้อควรรู้

- เป็น**การกระทำที่ตั้งใจสั่งเอง** รันเมื่อพิมพ์คำสั่งเท่านั้น
- **ตัดการเชื่อมต่อเครื่องลูกชั่วคราว** (ไม่กี่วินาที) ระหว่าง server กลับมา — เป็นเรื่องปกติ
- ห้ามรันตอนมีคนกำลังรีโมตงานสำคัญอยู่ (เซสชันจะหลุด)
- เกี่ยวข้อง: [MOVING-THE-SERVER.md](MOVING-THE-SERVER.md) (ย้าย server), บทเรียนเรื่อง `service:start`/orphan อยู่ในสคริปต์เอง
