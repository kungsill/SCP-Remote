# SCP-Remote native agent — Direct transport preview

สถานะ: รุ่นทดสอบ ยังไม่ติดตั้งแทนเอเจนต์ในโรงพยาบาล และยังไม่ถือว่าผ่านการทดสอบหน้าจอจริง

## สิ่งที่ตรวจพบและแก้ไข

ทดสอบ Chrome กับ MeshAgent เดิมบนเครื่องพัฒนา: ICE เชื่อมต่อได้ แต่ DTLS ล้มเหลวและ DataChannel ไม่เปิด การแก้ใน JavaScript เพียงอย่างเดียวไม่พอ

แพตช์ `ecdsa-dtls.patch` สร้างใบรับรอง ECDSA P-256 สำหรับโรงงาน WebRTC แยกจากใบรับรอง RSA ของเอเจนต์ที่ใช้ติดต่อเซิร์ฟเวอร์ การพิสูจน์ fingerprint ใน SDP ยังคงเดิม ไม่มีการปิดการตรวจใบรับรองหรือเปลี่ยน certificate pin ของเซิร์ฟเวอร์ และโมดูล native ประกาศ `scpEcdsa=true` เพื่อให้เลือกใช้เฉพาะไบนารีที่รองรับ

ทดสอบไบนารีที่คอมไพล์แล้วกับ Chrome จริง: รับ–ส่งข้อความทดสอบสองทิศทางสำเร็จโดยใช้ `iceServers: []` และ fingerprint ที่ตั้งให้ผิดป้องกันการรับ–ส่งข้อมูลได้ ทดสอบนี้อยู่บนเครื่องพัฒนาเดียวกัน ไม่ยืนยันการเชื่อมข้าม VLAN, Wi-Fi หรือภาพ/อินพุต Windows จริง

## สร้างซ้ำ

- ซอร์ส: https://github.com/Ylianst/MeshAgent
- commit: `b82cbde6136e699ba240cd8f38220ee3264da337`
- Visual Studio Build Tools v142, Windows SDK 10.0.19041.0, Windows x64
- โคลนซอร์สลง `.local/build/MeshAgent` และ checkout commit ข้างต้น จากนั้นรัน `powershell -File hospital/native-agent/build.ps1`
- สคริปต์ตรวจ revision และแพตช์ สร้าง service executable แล้วคัดลอกไป `release/preview-...` ไม่ติดตั้ง service ไม่แทนไฟล์ agent downloads และไม่กระจายอัปเดตเครื่องลูก
- ทดสอบ: ตั้ง `SCP_TEST_AGENT` เป็นพาธไบนารีที่สร้าง แล้วรัน `node hospital/native-agent/test-transport.js` ต้องมี Chrome ติดตั้ง สคริปต์เปิด Chrome แบบ headless กับโปรไฟล์ทดสอบใน `.local/acceptance` ไม่เปิดรีโมตหรืออ่านคลิปบอร์ด
- เพิ่ม `SCP_TEST_BAD_FINGERPRINT=1` เพื่อทดสอบการปฏิเสธ fingerprint ไม่ตรง

## การสลับเส้นทาง

โมดูล `scp-lan` เริ่มจาก Relay และรอภาพแรกหลังการอนุญาตก่อนเจรจา Direct ไม่ใช้ช่องทางภายนอก ถ้าช่องตรงขาดจะคืนการส่งภาพ/อินพุตผ่าน WebSocket เดิม พร้อมขอภาพใหม่ ถ้าไม่ยืนยันการคืนช่องทางภายใน 5 วินาทีจะยุติเซสชัน ไม่ถือว่าเชื่อมต่อสำเร็จ

คง Relay สำหรับดูอย่างเดียวและเซสชันที่เซิร์ฟเวอร์กำลังบันทึก ใช้สิทธิ์ควบคุมเดิม และเอเจนต์ต้องมี KVM ที่เปิดหลังอนุญาตแล้วก่อนรับข้อเสนอ

## ก่อนใช้งานจริง

ยังต้องทดสอบกับเครื่องทดสอบที่มีเจ้าหน้าที่: ขออนุญาต/ปฏิเสธ หยุดรีโมต อินพุตสองทาง ภาพต่อเนื่อง ถอด Wi-Fi เพื่อทดสอบ fallback คลิปบอร์ด การกลับออนไลน์ของ service และการย้อนกลับไปไบนารีเดิม ไบนารี preview ยังไม่ได้เซ็นโค้ด ห้ามกระจายแทนทั้งโรงพยาบาลจากผลทดสอบข้อความอย่างเดียว

คงข้อความลิขสิทธิ์และเงื่อนไขอนุญาตของ MeshAgent และส่วนประกอบ OpenSSL/Duktape ในซอร์สต้นฉบับ การสร้างนี้เป็นการปรับแต่งภายในโครงการ SCP-Remote
