# ศูนย์งาน IT และการตรวจรับ

เปิด **แดชบอร์ด → แจ้งซ่อม / ตรวจระบบ** รองรับภาษาไทยและอังกฤษ

## แจ้งซ่อมและประวัติ

เลือกเครื่อง ระบุปัญหา รายละเอียด หน่วยงาน และผู้ติดต่อ แล้วบันทึก สามารถมอบหมายบัญชีผู้รับผิดชอบ เปลี่ยนเป็นกำลังซ่อม รอดำเนินการ หรือปิดงานได้ การปิดงานต้องมีผลซ่อม ทุกครั้งเก็บผู้ดำเนินการและเวลา เปิดประวัติรายเครื่องผ่านตัวกรอง และเปิดรีโมตจากรายละเอียดงานได้

ข้อมูลเก็บในฐานข้อมูลเดิมชนิด `scpticket` จึงรวมในการสำรองฐานข้อมูล ใช้สิทธิ์เข้าถึงเครื่องของผู้ใช้ในการอ่านและบันทึก ป้องกันการแก้ไขทับกันด้วย revision; หากมีผู้แก้ก่อนแล้วต้องเปิดข้อมูลใหม่ ไม่ได้เปิดช่องแจ้งซ่อมสาธารณะหรือส่งอีเมลออกภายนอก

## เครื่องลูกและภาพแรก

งานติดตั้งไดรเวอร์แสดงขั้นค้นหา ดาวน์โหลด และติดตั้งจากเอเจนต์รุ่น `2026.09.16.4` ขึ้นไป เก็บผลตอบกลับล่าสุดรายเครื่องในฐานข้อมูลชนิด `scpdriver` เปิดแดชบอร์ดใหม่จะอ่านผลกลับตามสิทธิ์ของผู้ใช้ และตรวจซ้ำทุก 10 วินาที หากรอเกิน 15 นาทีแสดงว่ายังไม่ทราบผล แต่ยังรับคำตอบที่มาช้าได้ เครื่องที่ติดคำสั่งอื่นจะรายงานว่าไม่ได้เริ่มงาน ไม่ตีความคำตอบว่างว่าเป็นการติดตั้งสำเร็จ งานเก่าก่อนเปิดใช้การเก็บผลนี้อาจไม่มีรายงานย้อนหลัง และระบบไม่สั่งติดตั้งซ้ำอัตโนมัติ

แท็บเครื่องลูกแสดงเวอร์ชันที่รายงานล่าสุดทุกเครื่อง พร้อมสถานะออฟไลน์หรือยังไม่รายงาน หน้า Desktop แยกการเปิดช่องทางออกจากการได้รับภาพแรกจริง หากไม่มีภาพหรือความคืบหน้า 90 วินาทีมีปุ่มลองใหม่โดยผู้ใช้เป็นผู้กด

## คลังไดรเวอร์โรงพยาบาล

เฉพาะผู้ดูแลสูงสุดของโดเมนหลักเปิดแท็บ **คลังไดรเวอร์** ได้ ปุ่มอยู่บนแถบปุ่มของแดชบอร์ด และในหน้าต่างแจ้งซ่อม / ตรวจระบบ ผู้ใช้อื่นจะไม่เห็นปุ่มนี้ หลักคิดคือแยกสามขั้นออกจากกัน — ค้นหา เก็บไว้ที่เครื่องหลัก และติดตั้ง — แต่ละขั้นต้องมีคนสั่ง จะได้ไม่มีเครื่องในวอร์ดไหนถูกติดตั้งหรือรีสตาร์ตโดยไม่มีใครตัดสินใจ

**ค้นหา** สั่งเอเจนต์ถาม Windows Update เฉพาะไดรเวอร์ที่ยังไม่ได้ติดตั้ง ไม่ดาวน์โหลดและไม่ติดตั้งอะไรลงเครื่องลูกทั้งสิ้น รายการ BIOS และเฟิร์มแวร์ถูกข้ามโดยตั้งใจ เพราะไม่ใช่งานของขั้นตอนนี้ ค้นหาพร้อมกันครั้งละ 2 เครื่อง รับผลไม่เกินเครื่องละ 150 รายการ ถ้าเกิน 20 นาทีจะเลิกรอและรายงานว่าค้นหาเกินเวลา เครื่องที่กำลังติดคำสั่งอื่นจะรายงานว่ามีงานอื่นทำงานอยู่ แล้วลองใหม่ให้เองสูงสุด 5 ครั้ง ห่างกันครั้งละ 1 นาที เครื่องที่ปิดอยู่ค้างสถานะรอเครื่องออนไลน์ ไม่นับว่าล้มเหลว

**เก็บไว้ที่เครื่องหลัก** เครื่องหลักเป็นผู้ดาวน์โหลดเอง ครั้งละหนึ่งแพ็กเกจ รับลิงก์จากโดเมนของไมโครซอฟท์เท่านั้น (`*.windowsupdate.com`, `*.update.microsoft.com`, `download.microsoft.com`, `delivery.mp.microsoft.com`) และบังคับเป็น HTTPS เสมอ ไฟล์ที่โหลดมาต้องขึ้นต้นด้วยลายเซ็น `MSCF` ของแฟ้ม cab จริง ไม่เช่นนั้นทิ้ง แล้วบันทึก SHA-256 ไว้ ไฟล์เดียวไม่เกิน 2 GB คลังรวมไม่เกิน 20 GB และถ้าพื้นที่ว่างของดิสก์เหลือน้อยกว่า 3 GB จะไม่เริ่มโหลด แพ็กเกจที่ไม่มีลิงก์ดาวน์โหลดตรงจะขึ้นว่าไม่มีลิงก์ดาวน์โหลดตรง ต้องหาไฟล์จากผู้ผลิตเอง

**ติดตั้ง** เลือกได้เฉพาะเครื่องที่รายงานเองว่าต้องการแพ็กเกจนั้น และผลค้นหาต้องไม่เก่าเกิน 7 วัน ไม่เช่นนั้นระบบจะให้ค้นหาใหม่ก่อน เครื่องลูกดึงไฟล์จากเครื่องหลักด้วยตั๋วใช้ครั้งเดียวอายุ 30 นาที ตรึงใบรับรองของเครื่องหลักด้วย SHA-256 จึงใช้ได้กับใบรับรองที่ออกเองของโรงพยาบาล แล้วตรวจ SHA-256 ของไฟล์ซ้ำก่อนแตกไฟล์และส่งให้ `pnputil` ของ Windows เป็นผู้ตรวจลายเซ็นและตัดสินใจ **ไม่มีขั้นตอนใดรีสตาร์ตเครื่อง** ถ้า Windows แจ้งว่าต้องรีสตาร์ต ระบบจะเขียนไว้ในสถานะและปล่อยให้คนที่รู้ว่าเครื่องนั้นกำลังถูกใช้ทำอะไรเป็นผู้ตัดสินใจ ติดตั้งได้ครั้งละหนึ่งงานต่อเครื่อง เกิน 30 นาทีไม่มีคำตอบจะขึ้นว่ายังยืนยันผลไม่ได้ ไม่ถือว่าสำเร็จ และเมื่อสำเร็จก็ยังต้องไปดูสถานะอุปกรณ์อีกครั้ง เพราะ Windows อาจเลือกคงไดรเวอร์เดิมที่จัดอันดับสูงกว่าไว้

### เพิ่มไดรเวอร์จากเครื่องคุณเอง

วอร์ดที่ออกอินเทอร์เน็ตไม่ได้เลยจะใช้การค้นหาจาก Windows Update ไม่ได้ ทางออกคือ IT หาไฟล์ไดรเวอร์มาเองแล้วเอาเข้าคลัง จากนั้นเครื่องลูกดึงจากเครื่องหลักด้วยเส้นทางเดิมทุกอย่าง — ตั๋วใช้ครั้งเดียว ตรึงใบรับรอง ตรวจ SHA-256 แล้วให้ `pnputil` เป็นคนตัดสิน

กดที่ **เพิ่มไดรเวอร์จากเครื่องนี้** ในแท็บคลังไดรเวอร์ ใส่ชื่อที่จะให้แสดง ยี่ห้อ และรุ่นเครื่องที่ใช้แพ็กนี้ (สองอย่างหลังไม่บังคับ แต่ใส่ไว้จะกันหยิบแพ็กผิดยี่ห้อ)

**รับเฉพาะ `.zip` กับ `.cab`** ไฟล์ `.exe` ที่แตกตัวเองไม่รับ เพราะการสั่งรันตัวติดตั้งของผู้ผลิตด้วยสิทธิ์ SYSTEM บนเครื่องที่มีข้อมูลคนไข้ คือสิ่งที่ระบบนี้ตั้งใจเลี่ยงมาตลอด ถ้าไฟล์ที่ได้มาเป็น `.exe` ให้แตกบนเครื่องคุณก่อน แล้วบีบโฟลเดอร์ที่มีไฟล์ `.inf` เป็น `.zip` ส่งเข้ามาแทน

แหล่งไฟล์ที่แนะนำคือชุดไดรเวอร์ทางการของผู้ผลิตเครื่อง เช่น Dell Command | Deploy, HP DPK/SoftPaq, Lenovo SCCM Driver Pack เพราะเซ็นมาจากผู้ผลิตโดยตรง ตรวจที่มาได้ และโหลดครั้งเดียวใช้ได้ทั้งห้องที่เป็นรุ่นเดียวกัน

**สิ่งที่เครื่องหลักตรวจก่อนรับไฟล์** ทำครั้งเดียวตอนอัปโหลด ขณะไฟล์ยังอยู่บนเครื่องหลัก:

- ตรวจ 4 ไบต์แรกว่าเป็น `.cab` หรือ `.zip` จริง ไม่ดูจากนามสกุลไฟล์
- ถ้าเป็น zip ตรวจ**ชื่อทุกรายการข้างใน** ถ้ามีรายการไหนพาธหลุดออกนอกโฟลเดอร์ที่จะแตก (`..`, พาธที่ขึ้นต้นด้วย `/` หรือ `\`, หรือระบุไดรฟ์) จะไม่รับทั้งไฟล์
- ต้องมีไฟล์ `.inf` อย่างน้อยหนึ่งไฟล์ ไม่งั้นไม่ใช่ไดรเวอร์
- บันทึก SHA-256 ไว้ แล้วเก็บไฟล์โดยใช้ค่าแฮชเป็นชื่อ ไฟล์เดียวกันอัปโหลดซ้ำจึงไม่กินที่เพิ่ม และระบบจะบอกว่ามีอยู่แล้ว

ที่ตรวจชื่อรายการตอนอัปโหลดครั้งเดียวได้ เพราะ SHA-256 มัดไว้แล้วว่าไฟล์ที่เครื่องลูกแตกออกมา เป็นไฟล์เดียวกับที่ตรวจบนเครื่องหลักทุกไบต์

**เวลาติดตั้ง** แพ็กที่อัปโหลดเองเลือกเครื่องได้ทุกเครื่องที่เป็น Windows ไม่จำกัดเฉพาะเครื่องที่มีผลค้นหา เพราะไม่มีผลค้นหาของ Windows Update อยู่เบื้องหลังให้เทียบ — คนที่อัปโหลดเป็นคนเลือกเองว่าแพ็กนี้ใช้กับเครื่องไหน ส่วนแพ็กที่มาจาก Windows Update ยังต้องมีผลค้นหาไม่เกิน 7 วันที่ระบุแพ็กนั้นเหมือนเดิม ข้อบังคับอื่นใช้เหมือนกันหมด คือเครื่องต้องออนไลน์ ติดตั้งครั้งละงานเดียวต่อเครื่อง และไม่รีสตาร์ตเครื่องให้

### พื้นที่จัดเก็บ

ไฟล์อยู่ในโฟลเดอร์ `scp-driver-library` ข้าง ๆ โฟลเดอร์ข้อมูล ไม่ได้รวมอยู่ในไฟล์สำรองฐานข้อมูล ซึ่งตั้งใจไว้เช่นนั้น เพราะเป็นไฟล์ที่ดาวน์โหลดใหม่ได้เสมอและจะทำให้ชุดสำรองใหญ่โดยไม่จำเป็น

ตัวเลขพื้นที่ใช้งานด้านบนนับจากโฟลเดอร์จริง ไม่ใช่จากรายการแพ็กเกจ เพราะการดาวน์โหลดที่ถูกขัดจังหวะจะทิ้งไฟล์ `.part` ไว้ และไฟล์เหล่านั้นก็กินดิสก์ของเครื่องหลักเท่ากับไฟล์ปกติ ระบบกวาดไฟล์ที่ไม่มีแพ็กเกจใดอ้างถึงทิ้งทุกครั้งที่เริ่มและจบการดาวน์โหลด

ปุ่ม **ลบออกจากเครื่องหลัก** ในแต่ละแพ็กเกจใช้คืนพื้นที่ และจะบอกว่าคืนมาได้เท่าไร ระบบจะไม่ลบให้เมื่อแพ็กเกจนั้นกำลังดาวน์โหลดอยู่ หรือมีงานติดตั้งที่ยังไม่รายงานผลกลับมา เพราะเครื่องลูกอาจกำลังดึงไฟล์นั้นอยู่ ไฟล์ที่แพ็กเกจอื่นยังใช้ร่วมกันจะไม่ถูกลบ

การลบแพ็กเกจ **ไม่ได้ถอนไดรเวอร์ออกจากเครื่องที่ติดตั้งไปแล้ว** เครื่องนั้นยังใช้ไดรเวอร์เดิมต่อไปตามปกติ และถ้าต้องใช้แพ็กเกจนั้นอีก การค้นหาใหม่จะโหลดกลับมาได้ เมื่อคลังเต็มหรือดิสก์ใกล้เต็ม แพ็กเกจจะขึ้นว่าไม่สำเร็จพร้อมเหตุผล และทางแก้คือลบแพ็กเกจที่ไม่ใช้แล้วออกก่อน แล้วกดดาวน์โหลดอีกครั้ง

### ลงไดรเวอร์จริง เมื่อจำเป็น — วิธีที่เชื่อถือได้

การค้นหาผ่าน Windows Update **ไม่สามารถโหลดไฟล์มาเก็บที่เครื่องหลักได้** เพราะ Windows Update ไม่ให้ลิงก์ดาวน์โหลดตรงสำหรับไดรเวอร์ส่วนใหญ่ (มีแต่ตัว Windows Update Agent บนเครื่องนั้นเองที่ดึงได้ ผ่านช่องทางของมัน) การค้นหาจึงมีไว้เพื่อ **บอกว่าเครื่องขาดอะไร** ไม่ใช่เพื่อโหลดมาแจก

เมื่อต้องลงไดรเวอร์จริง ให้ทำตามนี้:

**1. แยกก่อนว่าเป็นปัญหาจริงหรือแค่ป้ายเหลือง cosmetic** — อุปกรณ์ชิปเซ็ตที่ Windows ไม่มีชื่อให้ (SM Bus Controller, PCI Simple Communications Controller, Base System Device และ PCI/System อื่น ๆ) เป็น cosmetic เครื่องทำงานได้ปกติโดยไม่ต้องมีไดรเวอร์พวกนี้ **ไม่ต้องไปหา** แผงจะไม่ตีเป็น "ต้องดูแล" อยู่แล้ว ที่ต้องลงจริงคืออุปกรณ์ที่ใช้งานไม่ได้ เช่น ไม่มีเสียง เน็ตไม่ติด กล้องไม่ขึ้น

**2. ดูรุ่นเครื่องให้แม่น** — เปิดคลังไดรเวอร์ แท็บ "สถานะค้นหาและติดตั้งแยกตามเครื่อง" จะบอกยี่ห้อและรุ่น (เช่น `LENOVO 10ASS03J00`, `HP 205 Pro G8`) เลขรุ่นนี้คือ Machine Type ที่ใช้ค้นหาที่เว็บผู้ผลิต

**3. โหลดจากผู้ผลิตตามรุ่น** — นี่คือแหล่งที่เชื่อถือได้ เพราะเซ็นถูกต้องและตรงรุ่น:

- **Lenovo** — support.lenovo.com ใส่ Machine Type แล้วเลือกไดรเวอร์ที่ต้องการ (Lenovo มีชุด SCCM/Driver Pack รวมทุกตัวของรุ่นนั้น)
- **HP** — support.hp.com ใส่ชื่อรุ่น หรือใช้ HP Image Assistant
- **Intel / Realtek โดยตรง** — สำหรับ chipset (Intel Chipset Device Software), MEI, หรือเสียง Realtek เว็บผู้ผลิตชิปให้โหลดตรงตาม hardware ID ได้
- Acer / MSI / Gigabyte — เว็บ support ตามรุ่น

**อย่าใช้ DriverPack หรือแหล่งรวมไดรเวอร์จากคนกลาง** — INF มักถูกดัดแปลง ลายเซ็นพัง แล้ว Windows 64-bit จะปฏิเสธตอนติดตั้ง (ระบบเราปล่อยให้ `pnputil` ตรวจลายเซ็นเอง ซึ่งเป็นการออกแบบที่ถูก)

**4. เตรียมไฟล์ให้ถูกแบบ** — ต้องเป็น `.zip` ของโฟลเดอร์ที่มีไฟล์ `.inf` หรือ `.cab` จากผู้ผลิต **ไม่รับ `.exe` ที่แตกตัวเอง** ถ้าโหลดมาเป็น `.exe` ให้แตกบนเครื่องคุณก่อน แล้วบีบโฟลเดอร์ที่มี `.inf` เป็น `.zip`

**5. อัปโหลดเข้าคลัง** — คลังไดรเวอร์ → **เพิ่มไดรเวอร์จากเครื่องนี้** → เลือกไฟล์ → ใส่ชื่อ/ยี่ห้อ/รุ่น → **เพิ่มเข้าคลัง** ระบบตรวจชนิดไฟล์ พาธในไฟล์ และบันทึก SHA-256 ให้ (ดูรายละเอียดในหัวข้อ *เพิ่มไดรเวอร์จากเครื่องคุณเอง* ด้านบน)

**6. ติดตั้ง** — เลือกเครื่องปลายทางในการ์ดแพ็กเกจ → **ติดตั้งบนเครื่องที่เลือก** เครื่องลูกดึงไฟล์จากเครื่องหลักด้วยตั๋วใช้ครั้งเดียว ตรวจ SHA-256 ซ้ำ แล้วให้ `pnputil` ตัดสิน **ไม่มีการรีสตาร์ตเครื่อง** ถ้า Windows แจ้งว่าต้องรีสตาร์ต จะเขียนไว้ในสถานะให้ตัดสินใจเอง

**7. ตรวจซ้ำ** — หลังติดตั้งสำเร็จ ให้ดูสถานะอุปกรณ์อีกครั้ง เพราะ Windows อาจเลือกคงไดรเวอร์เดิมที่จัดอันดับสูงกว่าไว้

> ตัวอย่างที่ทำสำเร็จแล้ว: Intel MEI ("PCI Simple Communications Controller") — ดึงไฟล์ต้นฉบับที่เซ็นโดย Microsoft WHQL บีบเป็น `.zip` (1.9 MB) อัปโหลดเข้าคลัง แล้วติดตั้งได้ตามขั้นตอนนี้

## รับ–ส่งไฟล์

แท็บไฟล์ของเครื่องลูกแสดงทิศทาง เครื่องและพาธปลายทาง รายชื่อไฟล์ในคิว สถานะรายไฟล์ และอัตราโอนเฉลี่ยระหว่างทำงาน ใช้ปุ่มยกเลิกของหน้าต่างโอนเดิม หากล้มเหลวหรือยกเลิกจะมีปุ่มลองใหม่ โดยตรวจว่าเป็นเครื่องและโฟลเดอร์เดิม การอัปโหลดสำเร็จอิงคำตอบจากเอเจนต์ การดาวน์โหลดสำเร็จหมายถึงข้อมูลมาถึงเบราว์เซอร์ครบ ไม่ใช่การยืนยันว่าผู้ใช้บันทึกลงดิสก์แล้ว

คิวเก็บเฉพาะช่วงที่หน้าเว็บเปิดอยู่ หลังโหลดหน้าใหม่ต้องเลือกไฟล์ใหม่ การอัปโหลดซ้ำที่มีชื่อเดิมยังใช้การยืนยันเขียนทับและตรวจ hash ตามระบบเดิม

## สำรองและกู้คืน

เฉพาะผู้ดูแลสูงสุดของโดเมนหลักเปิดแท็บสำรองข้อมูลได้ แสดงไฟล์ล่าสุดของสำรองหลักและอีกไดรฟ์ เตือนเมื่อเกิน 36 ชั่วโมง และเทียบ SHA-256 ของสำเนาไฟล์ล่าสุดที่ชื่อและขนาดตรงกัน (ตรวจไฟล์ไม่เกิน 256 MiB)

ปุ่มทดสอบสำรองล่าสุดจะตรวจความสมบูรณ์ ZIP แตกไฟล์ใน `.local/scp-restore-checks` ตรวจ JSON ของ config และ NeDB แล้วเปิดเซิร์ฟเวอร์ชั่วคราวด้วยค่าตั้งที่จำกัดเฉพาะ `127.0.0.1` และพอร์ตว่าง ตรวจหน้าเข้าสู่ระบบก่อนปิดโปรเซส ไม่เขียนทับข้อมูลจริง ไม่ย้าย IP และไม่สั่งเครื่องลูกเชื่อมต่อไปยังเซิร์ฟเวอร์ทดสอบ ผลเก็บใน `scp-backup-verification.json` ของโฟลเดอร์ข้อมูล

การทดสอบนี้รองรับชุดสำรอง NeDB ของเครื่องนี้ ขนาด ZIP สูงสุด 256 MiB และขนาดแตกไฟล์รวม 512 MiB ไม่รองรับการกู้ฐานข้อมูล MongoDB/SQL ผ่านขั้นตอนนี้ เก็บโฟลเดอร์ทดสอบไว้ตรวจสอบภายหลังและไม่รวมไว้ในโฟลเดอร์ข้อมูลหลัก การซ้อมย้ายเซิร์ฟเวอร์และให้เอเจนต์กลับมาเชื่อมต่อเป็นอีกขั้นตอนหนึ่ง
