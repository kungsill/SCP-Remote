# สเปก: แอป SCP-Remote บน Android (เนทีฟ แบบ AnyDesk)

วันที่ 14 พฤศจิกายน 2569 · ผู้ดูแลเลือกทาง C (แอปเนทีฟทั้งตัว ไม่ใช้หน้าเว็บ) และเลือกสิทธิ์แบบ "สิทธิ์ต่อบัญชี"

## เป้าหมาย

ช่าง IT ใช้มือถือ Android ติดตั้งแอปจากไฟล์ APK เข้าสู่ระบบด้วยบัญชี SCP-Remote ค้นหาเครื่อง แล้วรีโมตหรือแก้ปริ้นได้ โดยการควบคุมเหมาะกับนิ้วแบบ AnyDesk

## สิทธิ์ต่อบัญชี

ใช้สิทธิ์ของบัญชี SCP-Remote ที่ตั้งบนเว็บ เซิร์ฟเวอร์คำนวณสิทธิ์ต่อเครื่องและส่งให้แอป แอปไม่คำนวณสิทธิ์เอง และเซิร์ฟเวอร์ตรวจซ้ำทุกคำสั่ง

| บิตสิทธิ์ (MeshCentral) | ในแอป |
| --- | --- |
| ไม่มี `REMOTECONTROL` (0x8) หรือมี `NODESKTOP` (0x10000) | ไม่มีปุ่มเชื่อมต่อ |
| มี `REMOTEVIEWONLY` (0x100) | เชื่อมต่อแบบดูอย่างเดียว (`viewonly`) ปิดเมาส์และคีย์บอร์ด |
| มี `REMOTECOMMAND` (0x20000) | มีปุ่มแก้ปริ้น |
| ผู้ดูแลระบบสูงสุด (siteadmin = 0xFFFFFFFF) หรือสิทธิ์ 0xFFFFFFFF | ทำได้ทั้งหมด |

คนที่หน้าเครื่องยังถูกถามอนุญาตตามนโยบายของเซิร์ฟเวอร์ และทุกครั้งถูกบันทึกในหน้าเหตุการณ์

## โครงสร้าง

- **ภาษา/แพลตฟอร์ม:** Kotlin, minSdk 26 (Android 8.0), compile/target SDK 36, ไลบรารี WebSocket คือ OkHttp 4.12.0 ไม่ใช้ WebView ในการรีโมต
- **เข้าสู่ระบบ:** WebSocket `wss://<server>/control.ashx` พร้อม header `x-meshauth: base64(user),base64(pass)` (วิธีเดียวกับเครื่องมือ meshctrl)
- **รายชื่อเครื่องและสิทธิ์:** คำสั่งใหม่ของเซิร์ฟเวอร์ `scpops` op `appDevices` (คำนวณด้วย `GetNodeWithRights`)
- **รีโมต:** ขอ `authcookie` → ส่ง `{action:'msg', type:'tunnel', nodeid, usage:2, value:'*/meshrelay.ashx?p=2&nodeid=…&id=…&rauth=…'}` (+`viewonly:true` ถ้าดูอย่างเดียว) → เปิด `wss://<server>/meshrelay.ashx?browser=1&p=2&nodeid=…&id=…&auth=…` → รอข้อความ `c` หรือ `cr` → ส่ง `"2"` → รับข้อมูลไบนารี
- **โปรโตคอลภาพ/อินพุต:** ตรงกับ `public/scripts/agent-desktop-0.0.2.js` และ `agent-redir-ws-0.1.1.js` (รายละเอียดในแผน)
- **รักษาการเชื่อมต่อ:** ส่ง `{"ctrlChannel":102938,"type":"rtt","time":…}` ทุก 10 วินาทีตลอดเซสชัน (บทเรียน 13 พ.ย.)
- **ต่อใหม่อัตโนมัติ:** เซสชันที่ได้ภาพแล้วหลุดเอง ลองใหม่ 3 ครั้ง รอ 2, 5, 10 วินาที ไม่ต่อใหม่ถ้าผู้ใช้ตัดเอง ถูกปฏิเสธ หรือออกจากหน้าจอรีโมต
- **ใบรับรอง:** ที่อยู่ IP ในวง LAN ปักหมุดลายนิ้วมือ SHA-256 จาก `hospital/desktop-app/server.json` · ชื่อโดเมน (`remote.kpsnana.com`) ใช้การตรวจใบรับรองปกติของ Android
- **พื้นหลัง:** แอปถูกพับไปเกิน 30 วินาที → ปิดเซสชันรีโมต (ไม่ปล่อยให้เครื่องคนอื่นถูกเปิดค้าง)
- **อัปเดตตัวเอง:** `public/app-update/android/android.json` (`versionCode`, `versionName`, `sha256`, `size`, `apk`) → ดาวน์โหลด ตรวจ SHA-256 → ส่งให้ Android ติดตั้ง (ผู้ใช้กดยืนยันเอง)

## ฝั่งเซิร์ฟเวอร์ที่ต้องเพิ่ม (ต้องรีสตาร์ตหนึ่งครั้ง)

- `operations.js`: op `appDevices` และ `fixPrinter` (op หลังเรียก `hospital/mobile.js` `run()` ซึ่งตรวจไว้แล้ว แต่ตรวจ `REMOTECOMMAND` ก่อน)
- `hospital/android-app/publish-apk.js`: วาง APK และ `android.json` ที่ `public/app-update/android/` ไม่ต้องรีสตาร์ต

## ข้อจำกัดและความเสี่ยงที่ผู้ดูแลรับทราบ

- Cloudflare Access ที่ยังเปิดอยู่จะกัน `control.ashx` จากอินเทอร์เน็ต ใน LAN ใช้ได้ปกติ
- APK ติดตั้งนอก Play Store, Android เตือนแหล่งที่ไม่รู้จัก, กุญแจเซ็นแอปต้องเก็บรักษา ถ้าหายต้องลบแล้วลงใหม่ทุกเครื่อง
- ทดสอบอัตโนมัติด้วย JUnit และโปรแกรมจำลอง Android ในเครื่องนี้ ต้องมีการทดสอบบนมือถือจริงก่อนใช้งาน
