# SCP-Remote Desktop 0.1.0 — Windows x64

โปรแกรมรีโมตสำหรับเจ้าหน้าที่ แยกจากเว็บไซต์ผู้ดูแล ใช้เอเจนต์และเซิร์ฟเวอร์ SCP-Remote ชุดเดิม

## เปิดใช้งาน

เปิด `hospital/desktop-app/release/SCP-Remote-win32-x64/SCP-Remote.exe` ต้องเก็บไฟล์และโฟลเดอร์ข้างเคียงไว้ด้วย เป็นโปรแกรมแบบ portable ยังไม่ใช่ตัวติดตั้งไฟล์เดียว

1. เปิดครั้งแรก โปรแกรมแสดงชื่อเครื่องและรหัสลงทะเบียน
2. ผู้ดูแลเข้าเว็บ → **แจ้งซ่อม / ตรวจระบบ → โปรแกรมรีโมต** ตรวจชื่อและรหัส เลือกห้องที่ให้เข้าถึง แล้วอนุมัติ
3. โปรแกรมตรวจสถานะทุก 10 วินาที เมื่ออนุมัติแล้วจะเห็นเครื่องโดยไม่ต้องกรอกบัญชี ครั้งถัดไปจำเครื่องเดิมด้วยคีย์ที่เข้ารหัสด้วย Windows
4. เลือกห้อง ค้นชื่อหรือ IP แล้วกด **ขอรีโมต** โปรแกรมเปิดหน้าจอแชร์ของ SCP-Remote และเริ่มขออนุญาตอัตโนมัติ
5. เครื่องลูกต้องกดอนุญาตก่อน ผู้ดูแลเว็บสามารถยกเลิกสิทธิ์โปรแกรมและตัด share ที่มีอยู่ได้
6. ปลายทางมีแถบแสดงการรีโมตพร้อมปุ่มหยุดตามความสามารถของเอเจนต์ Windows ต้องทดสอบปุ่มนี้จริงก่อนนำรุ่นแรกไปใช้งานเต็มรูปแบบ

## ผังห้อง

เว็บผู้ดูแล → **แจ้งซ่อม / ตรวจระบบ → ผังห้อง** กำหนดคอลัมน์และแถว 1–10 ตามโต๊ะจริง โปรแกรมแสดงตามข้อมูลนี้ เครื่องที่ยังไม่กำหนดตำแหน่งจะเรียงอัตโนมัติ ซึ่งไม่ใช่แผนผังสถานที่จริง

## ขอบเขตและการเชื่อมต่อ

- โปรแกรมเห็นเฉพาะห้องที่ได้รับอนุมัติ รองรับภาษาไทยและอังกฤษ พร้อม Sarabun ในตัว
- ใช้ HTTPS ไปยังเซิร์ฟเวอร์กลาง ไม่ต้องเปิดพอร์ต VNC รับจากเครื่องเจ้าหน้าที่ที่เครื่องลูก
- คีย์โปรแกรมไม่ใช่บัญชี admin ไม่ส่งให้ renderer และเซิร์ฟเวอร์เก็บเฉพาะ hash
- Share เปิดเฉพาะ Desktop และ Files ไม่เปิด Terminal และหมดอายุใน 2 ชั่วโมง
- การเข้าโปรแกรมต้องขออนุญาตแม้เจ้าของ share เป็น admin ที่มีสิทธิ์ unattended ปิดการยอมรับอัตโนมัติ และไม่ใช้ consent cache 5 นาที
- แยก tunnel ของโปรแกรมจาก desktop multiplex เพื่อให้ไม่อาศัยการอนุญาตของผู้ดูหน้าจอคนอื่น
- เครื่องลูกต้องรายงานเอเจนต์ `2026.09.20.1` หรือใหม่กว่า จึงใช้โปรแกรมนี้ได้
- โหมดภาพเริ่มต้น PNG (ไม่สูญเสียรายละเอียด), ความละเอียดต้นฉบับ 100%, ตั้งเพดานขอภาพประมาณ 20 ครั้ง/วินาที ไม่ใช่การรับประกัน FPS จริง โหมดพอดีหน้าต่างอาจยังย่อภาพตามขนาดจอผู้ดู
- การรับ–ส่งไฟล์ใช้แท็บ Files ของหน้าจอแชร์ การคัดลอกไฟล์จาก Explorer แล้ววางข้ามเครื่องโดยตรงยังไม่ได้เพิ่มในโปรแกรมนี้
- `server.json` กำหนดเซิร์ฟเวอร์และ SHA-256 ของใบรับรอง เมื่อย้ายเซิร์ฟเวอร์หรือเปลี่ยนใบรับรอง ผู้ดูแลต้องอัปเดตไฟล์นี้แล้วสร้างโปรแกรมใหม่ ไม่ยอมรับใบรับรองอื่นอัตโนมัติ

- ทดสอบสิทธิ์ห้อง การยกเลิกสิทธิ์ การบังคับ consent และตำแหน่งผังด้วย automated tests: ผ่าน
- ชุดทดสอบโรงพยาบาล 251 รายการและ HTTP checks: ผ่าน
- แถบหยุดที่ปลายทาง: ตรวจครบเส้นทางแล้วว่า consent `0x40` ส่งถึงเอเจนต์จริง (share บันทึก consent 109 → cookie `a:6` → เซิร์ฟเวอร์อ่าน `cf: doc.consent` จากฐานข้อมูลแล้วส่งต่อ) และเอเจนต์เครื่องทดสอบเคยแสดงแถบและถูกกดหยุดสำเร็จจริง 15 กันยายน (เหตุการณ์ 31 จำนวน 10 ครั้ง, เหตุการณ์ 29 จำนวน 4 ครั้ง, ไม่มีเหตุการณ์ 32 ที่แปลว่าแสดงแถบไม่ได้) แต่ครั้งนั้นรีโมตจากเว็บในฐานะ admin ยังไม่ได้ทดสอบผ่านเส้นทาง share ของโปรแกรม
- เชื่อมต่อจอจริงผ่านโปรแกรมจนสำเร็จ เครื่องปลายทางขึ้นหน้าต่างขออนุญาต ผู้ใช้กดอนุญาต แล้วแถบหยุดขึ้น: **ผ่าน** (20 กันยายน 2569 เวลา 13:29 กับเครื่องทดสอบ `10999`)
- แถบเครื่องมือของหน้า sharing (Connect/Disconnect/Settings/เวลาหมดอายุ) ถูกซ่อนในหน้าต่างของโปรแกรม เจ้าหน้าที่เห็นเฉพาะภาพหน้าจอ ปิดหน้าต่างเพื่อจบการเชื่อมต่อ
- ยังไม่ทดสอบ: การกดปฏิเสธ ความลื่นของภาพบน Wi-Fi การควบคุมเมาส์และคีย์บอร์ดเต็มรูปแบบ ไฟล์สองทาง และการกดปุ่มหยุดบนแถบที่ปลายทาง

## แก้แล้ว: กดขอรีโมตแล้วจอไม่ต่อ (20 กันยายน 2026)

**อาการ** กดขอรีโมตแล้วหน้าต่างรีโมตเปิดขึ้นและหน้า sharing โหลดได้ปกติ แต่สถานะค้างที่ ตัดการเชื่อมต่อแล้ว กดปุ่มเชื่อมต่อก็ไม่มีอะไรเกิดขึ้น ไม่มีข้อความผิดพลาด และเครื่องปลายทางไม่มีหน้าต่างขออนุญาตเด้งขึ้นเลย

**สาเหตุที่ตรวจพบ** ช่องทางรีโมตจริงเป็น WebSocket ไปที่ `wss://<เซิร์ฟเวอร์>/meshrelay.ashx` และถูกปฏิเสธด้วย `net::ERR_CERT_AUTHORITY_INVALID` เพราะเซิร์ฟเวอร์ใช้ใบรับรองที่ออกเอง โปรแกรมดักเหตุการณ์ `certificate-error` ไว้แล้วซึ่งครอบคลุมการโหลดหน้าเว็บ (หน้า sharing จึงขึ้นได้ตามปกติ) แต่ **Electron ไม่ยิงเหตุการณ์นั้นให้การเชื่อมต่อ WebSocket** ช่องรีโมตจึงตายเงียบโดยไม่มีข้อความแจ้งผู้ใช้

ยืนยันด้วยการเปิด `--remote-debugging-port` แล้วดักชั้น Network ของหน้า sharing เห็นลำดับ: สร้าง WebSocket ไป `meshrelay.ashx` แล้วตามด้วย frame error `ERR_CERT_AUTHORITY_INVALID` แล้วปิดทันที ฝั่งเซิร์ฟเวอร์ไม่มีเหตุการณ์ tunnel ใด ๆ ซึ่งตรงกับที่เอเจนต์ไม่เคยได้รับคำขอ

**แก้แล้ว** ผู้ดูแลเลือกแนวทางปักหมุดใบรับรองในโปรแกรม `main.js` จึงตรวจสอบใบรับรองระดับ session ซึ่งครอบคลุม WebSocket ด้วย โดยยอมรับเฉพาะ hostname และลายนิ้วมือที่ปักหมุดไว้ใน `server.json` เท่านั้น คำขออื่นทั้งหมดยังใช้ผลตรวจของ Chromium ตามปกติ นี่เป็นการปิดช่องที่เดิมไม่มีการตรวจสอบใด ๆ เลย ไม่ใช่การผ่อนการตรวจสอบ

หลังแก้ ทดสอบแล้วต่อจอได้จริง เครื่องปลายทางขึ้นหน้าต่างขออนุญาต และเมื่อกดอนุญาตแล้วแถบหยุดขึ้นตามปกติ

## ลากไฟล์ลงจอ → ส่งไปเดสก์ท็อปเครื่องปลายทาง

ในหน้าต่างรีโมตของโปรแกรม ลากไฟล์จากเครื่องคุณไปวางบนภาพหน้าจอเครื่องปลายทางได้เลย ไฟล์จะถูกส่งผ่าน**ช่องไฟล์**ไปไว้ที่ `C:UsersPublicDesktop` ของเครื่องปลายทาง ซึ่งจะโผล่บนเดสก์ท็อปของคนที่นั่งอยู่ รองรับไฟล์ใหญ่ (อัปโหลดแบบแบ่งชิ้นของ MeshCentral เอง) การลากไฟล์ครั้งแรกของ session อาจทำให้เครื่องปลายทางขึ้นกล่องขออนุญาตเข้าถึงไฟล์ — เป็นเรื่องปกติ คนปลายทางยังยินยอมก่อนถึงจะเขียนไฟล์ได้

**หมายเหตุ:** การลากไฟล์ลงจอนี้ **ไม่ได้รันไฟล์** (session ของโปรแกรมไม่มีสิทธิ์รันคำสั่ง มีแค่ desktop+files) ถ้าส่งไม่สำเร็จจะมีข้อความบอกให้ใช้แท็บ **ไฟล์** แทน ซึ่งเป็นช่องทางที่เชื่อถือได้เสมอ

โค้ดอยู่ที่ `hospital/desktop-app/inject-filedrop.js` (ฉีดเข้าหน้า sharing ผ่านโปรแกรม ไม่แก้ไฟล์ core ของ MeshCentral) — **ยังต้องทดสอบการลากจริงกับเครื่องจริงก่อนใช้เต็มรูปแบบ**

### ที่ทำไม่ได้: copy/paste ไฟล์ผ่านคลิปบอร์ด (Ctrl+C/Ctrl+V)

การก๊อป-วางไฟล์ผ่านคลิปบอร์ด Windows แท้ (CF_HDROP) ทำไม่ได้ เพราะต้องแก้เอเจนต์ที่เป็นไบนารีคอมไพล์แล้วให้จัดการคลิปบอร์ดชนิดไฟล์ ระบบรองรับคลิปบอร์ดแบบ **ข้อความ** เท่านั้น (ดูแท็บรับ–ส่งข้อความ) การลากไฟล์ลงจอด้านบนคือทางที่ใช้แทนได้

## แก้ปัญหาเปิดโปรแกรมไม่ติด

ถ้า `SCP-Remote.exe` เปิดแล้วดับทันทีโดยไม่มีข้อความใด ๆ ให้ตรวจตัวแปรสภาพแวดล้อม **`ELECTRON_RUN_AS_NODE`** ถ้าถูกตั้งค่าไว้ Electron จะรันเป็น Node.js ธรรมดา ทำให้ `app` เป็น undefined และโปรแกรมจบเงียบ ๆ โดยไม่แสดงหน้าต่างหรือข้อผิดพลาด

ตัวแปรนี้มักติดมาเมื่อเปิดโปรแกรมจาก terminal ที่ทำงานอยู่ภายในโปรแกรมฐาน Electron (เช่น VS Code หรือเครื่องมืออัตโนมัติ) **เปิดจาก File Explorer หรือ shortcut ตามปกติจะไม่เจอปัญหานี้** ถ้าจำเป็นต้องเปิดจาก terminal ให้ล้างตัวแปรก่อน:

```
$env:ELECTRON_RUN_AS_NODE = $null
```

วิธียืนยันว่าเป็นกรณีนี้: รัน `SCP-Remote.exe --enable-logging` ถ้าขึ้น `bad option: --enable-logging` แสดงว่ากำลังรันเป็น Node.js เพราะ Electron จริงรับตัวเลือกนี้ได้

## ไอคอนโปรแกรม

ไอคอน .exe และหน้าต่างใช้ `hospital/desktop-app/scp-logo.ico` (สร้างจากโลโก้ รพ. `public/images/scp-logo.png` ย่อเป็น 256/48/32/16 แล้วประกอบเป็น ICO) ต่อสายที่ `package.js` (`icon:`) และ `main.js` (`icon:` ของทั้งสองหน้าต่าง) ถ้าเปลี่ยนโลโก้ ให้สร้าง `.ico` ใหม่แล้ว build

## สร้างโปรแกรม

รันในโฟลเดอร์ `hospital/desktop-app`:

```
npm ci
npm run package
```

สคริปต์ package มี `--overwrite` ไว้แล้ว **อย่าถอดออก** ถ้าไม่มี `electron-packager` จะข้ามการสร้างเงียบ ๆ เมื่อโฟลเดอร์ release มีอยู่แล้ว (ขึ้นเพียงบรรทัด Skipping) ทำให้ได้ตัว .exe รุ่นเก่าทั้งที่คิดว่า build ใหม่แล้ว และอย่าลืมบีบไฟล์ zip ที่แจกใหม่ทุกครั้งหลัง build เพราะไม่ได้สร้างอัตโนมัติ

ตรวจ `package.json` ให้ไม่มี dependency ไปยังโฟลเดอร์เซิร์ฟเวอร์ โปรแกรมใช้เฉพาะ Electron และ Node built-ins เท่านั้น แพ็กเกจที่แจกใช้โฟลเดอร์ **release**; โฟลเดอร์ **dist** เป็น build ทดลองเก่าที่ไม่ใช้แจก

Electron/Chromium และ Sarabun มีไฟล์ใบอนุญาตแนบในชุดโปรแกรม รุ่นนี้ยังไม่ได้เซ็น executable ด้วยใบรับรอง code-signing ขององค์กร
