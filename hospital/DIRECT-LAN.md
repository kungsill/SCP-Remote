# Direct / Relay — สถานะพัฒนา 22 กันยายน 2569

## ทำแล้ว

- โมดูล JavaScript ฝั่งเว็บและเอเจนต์สำหรับเปลี่ยนจาก Relay ไป WebRTC หลังได้รับภาพแรก ไม่ข้ามขั้นตอนขออนุญาต
- ถ้าเจรจาไม่ได้ คง Relay เดิม หากเส้นทางตรงที่ใช้อยู่ขาดจะขอคืน Relay ในเซสชันเดิมและรีเฟรชภาพ หากเอเจนต์ไม่ยืนยันภายใน 5 วินาทีจะปิดเซสชัน
- ไม่มี ICE server ภายนอก ใช้ host candidates; ป้าย Direct ยืนยันเส้นทาง WebRTC ไม่ได้ยืนยันว่าอุปกรณ์อยู่ subnet เดียวกัน
- ปฏิเสธการ upgrade เมื่อดูอย่างเดียว ไม่มีสิทธิ์ควบคุม ยังไม่ได้เปิด KVM หรือเซิร์ฟเวอร์กำลังบันทึกเซสชัน
- สร้างไบนารี Windows x64 ที่แก้ปัญหา DTLS โดยใช้ ECDSA P-256 แยกจากใบรับรองติดต่อเซิร์ฟเวอร์เดิม ดู [native-agent/README.md](native-agent/README.md)
- API จะรายงานความสามารถ Direct เมื่อ core อย่างน้อย `2026.09.21.5` และ native ประกาศ `scpLanNative=true` เท่านั้น ไม่ตีความการอัปเดต JavaScript ว่าได้แก้ native แล้ว

## ผลตรวจ

การทดสอบ native binary กับ Chrome บนเครื่องพัฒนาจริงรับ–ส่งข้อมูลทดสอบได้ทั้งสองทาง และ fingerprint ที่ไม่ตรงทำให้ DTLS ล้มเหลวโดยไม่มีข้อมูลหลุดผ่าน การทดสอบ logic ครอบคลุมการรอภาพแรก การสลับท่อสองทาง การเจรจาหมดเวลา และการปิดเซสชันหากคืน Relay ไม่สำเร็จ

## ยังไม่เปิดใช้งานทั่วระบบ

ไม่ได้แทน `C:\Program Files\Mesh Agent\MeshAgent.exe` ไม่แก้ชุด agent downloads ไม่ติดตั้ง service ใหม่ และไม่ได้ restart เซิร์ฟเวอร์เพื่อกระจาย core ในรอบนี้

แอปรุ่น source 0.4.0 เตรียมตัวเลือก `directLan: true` ใน `server.json` สำหรับทดสอบโดยผู้พัฒนา ค่าเริ่มต้นยังไม่เปิด เว็บมี `scpLanEnabled` เป็นสวิตช์ทดสอบและยังปิดโดยค่าเริ่มต้น ทั้งสองทางยังตรวจ capability ของเอเจนต์ด้วย

ก่อนเปิดให้ใช้งานต้องติดตั้ง preview บนเครื่องทดสอบที่เตรียมย้อนกลับได้ แล้วตรวจภาพจริง อินพุต การปฏิเสธ/หยุดจากเครื่องลูก การเปลี่ยน Wi-Fi/VLAN การกลับ Relay และการกลับออนไลน์ของ service การทดสอบข้อความบนเครื่องพัฒนาไม่ใช่การรับงานส่วนนี้ทั้งหมด
