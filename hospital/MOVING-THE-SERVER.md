# ย้ายเซิร์ฟเวอร์ไปเครื่องใหม่

เครื่องที่รันอยู่ตอนนี้ (`DESKTOP-TA7KT4Q`) เป็นเซิร์ฟเวอร์หลักชั่วคราว เอกสารนี้คือวิธีย้ายไปเครื่องจริงโดยไม่ต้องเดินไปยุ่งกับเครื่องลูกทีละเครื่อง

## สิ่งที่ผูกเครื่องลูกไว้กับเซิร์ฟเวอร์

เอเจนต์ทุกตัวเก็บสองอย่างไว้ในไฟล์ `.msh` ของตัวเอง

| ค่า | ตอนนี้คือ | ถ้าไม่ตรงจะเกิดอะไร |
| --- | --- | --- |
| `MeshServer` | `wss://192.168.2.25:8443/agent.ashx` | ต่อไม่ติด เครื่องหายจากระบบ |
| `ServerID` | แฮชของ `agentserver-cert-public.crt` | ต่อติดแต่ไม่เชื่อถือ ปฏิเสธการเชื่อมต่อ |

`ServerID` สำคัญกว่า เพราะเปลี่ยนทีหลังไม่ได้ง่าย ๆ **ใบรับรองชุดนี้อยู่ในไฟล์สำรองอัตโนมัติแล้ว** ตรวจสอบได้จากในไฟล์ zip จะมี `agentserver-cert-private.key` และ `agentserver-cert-public.crt` อยู่ ตราบใดที่ยังมีไฟล์สำรอง เครื่องใหม่จะสวมตัวตนเดิมได้

## เลือกวิธีตามสถานการณ์

### วิธี ก — จอง IP เดิมไว้ให้เซิร์ฟเวอร์ (ง่ายที่สุด ไม่ต้องแตะเครื่องลูกเลย)

ถือว่า `192.168.2.25` เป็น **ที่อยู่ของบริการ ไม่ใช่ของเครื่อง** เครื่องไหนทำหน้าที่เซิร์ฟเวอร์ เครื่องนั้นได้ IP นี้

1. กู้ไฟล์สำรองล่าสุดลงเครื่องใหม่ (ดูหัวข้อ **กู้ไฟล์สำรอง** ด้านล่าง)
2. ปิดบริการบนเครื่องเก่า และเอา `192.168.2.25` ออกจากเครื่องเก่า
3. ตั้ง `192.168.2.25` ให้เครื่องใหม่ แล้วเปิดบริการ
4. กันไม่ให้ IP นี้ถูกแจกให้เครื่องอื่นในอนาคต — จองไว้ที่ DHCP หรือใช้ IP คงที่และจดไว้

เครื่องลูกไม่รู้เลยว่ามีอะไรเปลี่ยน ไม่ต้องสั่งอะไรทั้งนั้น **ถ้าเป็นไปได้ให้ใช้วิธีนี้**

### วิธี ข — ใช้ IP เดิมไม่ได้ ต้องเปลี่ยนที่อยู่

ทำได้ แต่มีเงื่อนไขสำคัญ: **ต้องทำตอนที่เซิร์ฟเวอร์เก่ายังเชื่อมต่อเครื่องลูกได้อยู่** เพราะต้องใช้การเชื่อมต่อเดิมเป็นทางส่งที่อยู่ใหม่ไปให้

1. กู้ไฟล์สำรองลงเครื่องใหม่ ตั้ง IP ใหม่ เปิดบริการ ตรวจว่าเข้าหน้าเว็บได้
2. **ยังไม่ปิดเครื่องเก่า** เข้าหน้าเว็บของเครื่องเก่า
3. เลือกเครื่องลูก เข้าแท็บ **คอนโซล** แล้วสั่งทีละสองบรรทัด

   ```
   msh set MeshServer "wss://192.168.2.30:8443/agent.ashx"
   service restart
   ```

   (เปลี่ยน `192.168.2.30` เป็น IP ใหม่จริง)
4. เครื่องนั้นจะหลุดจากเซิร์ฟเวอร์เก่า แล้วไปโผล่ที่เซิร์ฟเวอร์ใหม่ภายในไม่กี่วินาที
5. ทำให้ครบทุกเครื่อง แล้วค่อยปิดเครื่องเก่า

ทำทีละเครื่องช้าถ้ามีหลายสิบเครื่อง ใช้ **การดำเนินการกลุ่ม → รันคำสั่ง** สั่งพร้อมกันหลายเครื่องได้ แต่ช่องนั้นรันคำสั่งของ Windows ไม่ใช่คำสั่งของเอเจนต์ ให้สั่งแบบนี้แทน

```
"C:\Program Files\SCP-Remote\scpremote.exe" -msh:set MeshServer "wss://192.168.2.30:8443/agent.ashx"
```

เครื่องที่ติดตั้งก่อนเปลี่ยนชื่อแบรนด์จะอยู่ที่ `"C:\Program Files\Mesh Agent\MeshAgent.exe"` แทน **ลองกับเครื่องเดียวก่อนเสมอ** แล้วดูว่ามันไปโผล่ที่เซิร์ฟเวอร์ใหม่จริงก่อนสั่งทั้งกลุ่ม

### วิธี ค — ใช้ชื่อแทน IP (ทำได้เมื่อมี DNS ภายใน)

ตอนนี้ทำไม่ได้ เพราะโรงพยาบาลยังไม่มี DNS ภายใน เครื่องนี้ใช้ 1.1.1.1 กับ 8.8.8.8 ซึ่งเป็น DNS สาธารณะ และเราเตอร์ทั้งสองวง (192.168.2.1, 192.168.50.1) ไม่ได้ให้บริการ DNS

ถ้าวันหนึ่งมี DNS ภายใน (เช่นตั้ง Active Directory หรือเราเตอร์รุ่นที่ตั้งชื่อในวงได้) ให้ทำแบบนี้แล้วการย้ายครั้งต่อ ๆ ไปจะเหลือแค่แก้ DNS บรรทัดเดียว

1. สร้างระเบียน A เช่น `scpremote.sichomphu.local` ชี้มาที่ IP ของเซิร์ฟเวอร์ ให้ทุกวง (2.x, 50.x, 220.x) ถามชื่อนี้ได้
2. ตั้ง `settings.cert` ในไฟล์ตั้งค่าเป็นชื่อนั้น แล้วรีสตาร์ต เซิร์ฟเวอร์จะออกใบรับรองในชื่อใหม่ให้เอง
3. สร้างตัวติดตั้งใหม่ (`npm run build:setup-exe`) เครื่องที่ลงจากนี้ไปจะชี้ที่ชื่อ
4. เครื่องเดิมย้ายมาใช้ชื่อด้วยวิธี ข

ได้ใบรับรอง TLS ที่ตรงกับชื่อเป็นของแถม เบราว์เซอร์เลิกเตือน

## กู้ไฟล์สำรอง

1. ติดตั้ง Node.js และวางโค้ดชุดนี้บนเครื่องใหม่
2. แตกไฟล์ `meshcentral-autobackup-*.zip` เอาโฟลเดอร์ `scp-remote` ไปวางที่ `.local/scp-remote`
3. ก๊อป `signedagents/` จากสำเนาบนไดรฟ์สำรองมาวางด้วย (การสำรองอัตโนมัติข้ามโฟลเดอร์นี้ไว้ `npm run backup:copy` เป็นคนก๊อปให้)
4. แก้ IP ใน `config.json` ถ้าเปลี่ยน แล้ว `npm run build:hospital` และ `npm run service:install`

## กรณีเดียวที่ต้องเดินไปทุกเครื่อง

เซิร์ฟเวอร์พังกะทันหัน **และ** ใช้ IP เดิมไม่ได้ **และ** ไม่มีไฟล์สำรอง — สามอย่างพร้อมกัน ถ้ามีไฟล์สำรองอยู่ก็ยังรอดด้วยวิธี ก เสมอ นี่คือเหตุผลที่ไฟล์สำรองควรมีสำเนาอยู่นอกเครื่อง

## ก่อนย้ายจริง

ลองกับเครื่องทดสอบหนึ่งเครื่องให้ครบวงจรก่อน — กู้ไฟล์สำรอง เปิดบริการ ย้ายเครื่องลูกหนึ่งเครื่องมาหา แล้วรีโมตเข้าไปให้สำเร็จ จึงค่อยทำกับของจริง
