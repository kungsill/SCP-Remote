## หน้าตาและการใช้งาน

ธีม SCP-Remote ใช้พื้นหลังสว่าง สีเขียวอมฟ้า เมนูพร้อมชื่อ ช่องค้นหาเด่น และแบบฟอร์มเข้าสู่ระบบที่รองรับมือถือ โดยใช้แนวทางการ์ดและ navigation จาก [21st.dev](https://21st.dev/) เป็นแรงบันดาลใจ เขียน CSS/JavaScript ให้ทำงานกับระบบเดิม ไม่ได้ติดตั้ง React component หรือเรียกบริการ 21st.dev ระหว่างใช้งาน ฟอนต์ Sarabun และส่วนตกแต่งโหลดจากเซิร์ฟเวอร์ภายใน

ไฟล์ธีมอยู่ที่ `public/styles/scp-ui.css` และ `public/scripts/scp-ui.js` รองรับไทย/English และโหมดกลางคืนเดิม เมนูยังใช้สิทธิ์และคำสั่งเดิม ระบบคำนวณความสูงรายการอุปกรณ์และไฟล์ตามพื้นที่หน้าจอ หลังอัปเดตให้กด Ctrl+F5

ตรวจภาพด้วย `node scripts/review-hospital-ui.js` (ต้องมี Chrome บน Windows และเซิร์ฟเวอร์ทำงาน) ผลอยู่ใน `.local/ui-review/` การตรวจหน้าเข้าสู่ระบบใช้เซิร์ฟเวอร์จริง ส่วนหน้าจัดการใช้ template จำลองแบบแยกเพื่อไม่ต้องสร้างบัญชีหรือเชื่อมต่อเครื่องลูก

## สถานะเครื่องนี้ตอนนี้

ตั้งค่าเครื่อง `DESKTOP-TA7KT4Q` เป็นเซิร์ฟเวอร์หลักชั่วคราวแล้ว เมื่อย้ายไปเครื่องจริงต้องทำขั้นตอนในหัวข้อ **เปิดให้ใช้ในเครือข่ายโรงพยาบาล** ใหม่ทั้งหมด

| รายการ | ค่าที่ใช้ |
| --- | --- |
| ที่อยู่เซิร์ฟเวอร์ | `https://192.168.2.25:8443` (เข้าทาง `192.168.50.81` ได้เช่นกัน) |
| ที่อยู่ที่ฝังในตัวติดตั้งเอเจนต์ | `wss://192.168.2.25:8443/agent.ashx` |
| วงที่อนุญาต | `192.168.2.0/24`, `192.168.50.0/24`, `192.168.220.0/24`, `192.168.18.0/24` (เพิ่มวงใหม่ด้วย `node scripts/allow-subnet.js add ...`) |
| บริการ Windows | `SCP-Remote` เริ่มอัตโนมัติเมื่อเปิดเครื่อง |
| ไฟร์วอลล์ | กฎขาเข้า `SCP-Remote (TCP 8443)` จำกัดเฉพาะวงข้างต้น ปรับอัตโนมัติเมื่อใช้ `allow:subnet` |
| Intel AMT | ปิด (`mpsPort: 0`, `amtScanner: false`) โรงพยาบาลจัดการผ่านเอเจนต์อย่างเดียว |

ที่อยู่เซิร์ฟเวอร์ถูกฝังลงตัวติดตั้งเอเจนต์ตั้งแต่ตอนดาวน์โหลด แต่ **ไม่ได้แปลว่าย้ายเครื่องแล้วต้องเดินไปลงใหม่ทุกเครื่อง** ถ้ายกที่อยู่ `192.168.2.25` ไปให้เครื่องใหม่ เครื่องลูกไม่ต้องแตะเลย และถ้าต้องเปลี่ยนที่อยู่จริง ๆ ก็สั่งเปลี่ยนจากระยะไกลได้ก่อนปลดเครื่องเก่า ขั้นตอนทั้งหมดอยู่ใน [ย้ายเซิร์ฟเวอร์ไปเครื่องใหม่](MOVING-THE-SERVER.md)

ใช้งานจริงอยู่แล้ว มีบัญชีผู้ดูแลระบบ `admin` และเครื่องลูกเชื่อมต่ออยู่ ที่ยังเหลือคือใบรับรอง HTTPS ยังเป็นใบที่เครื่องสร้างเอง เบราว์เซอร์จึงเตือนว่าไม่น่าเชื่อถือ และบัญชี `admin` ยังไม่ได้เปิดการยืนยันสองชั้น (ค่าพร้อมแล้ว ดู [รับช่วงดูแลระบบ](HANDOVER.md))

## เริ่มใช้งานบนเครื่องนี้

ติดตั้ง Node.js 20 ขึ้นไป (ตรวจการทำงานครั้งนี้ด้วย Node.js 22.17.0) จากนั้นเปิด PowerShell ในโฟลเดอร์โครงการ:

```powershell
npm ci
npm run build:hospital
npm run start:hospital
```

เปิด **https://127.0.0.1:8443** สามารถเลือก **ไทย / English** ที่หน้าเข้าสู่ระบบได้ หลังเข้าสู่ระบบ เปลี่ยนภาษาได้ใน **บัญชีของฉัน → ตั้งค่าภาษาและภูมิภาค**

เครื่องนี้ติดตั้งแพ็กเกจและสร้างหน้าเว็บไว้แล้ว เปิดครั้งถัดไปด้วย `Start-SCP-Remote.cmd` หรือ `npm run start:hospital` ได้เลย

การเริ่มครั้งแรกจะคัดลอก `hospital/config.example.json` ไปยัง `.local/scp-remote/config.json` หากมีไฟล์อยู่แล้วจะไม่เขียนทับ ฐานข้อมูล ใบรับรอง และเอเจนต์ที่เซิร์ฟเวอร์ลงลายเซ็นจะอยู่ใน `.local/scp-remote/` ซึ่งไม่รวมใน Git

เซิร์ฟเวอร์ใหม่ที่ยังไม่มีผู้ใช้จะให้สร้างบัญชีแรกเป็นผู้ดูแลระบบ หลังจากนั้น `newAccounts: false` จะปิดการสมัครบัญชีทั่วไป ให้ผู้ดูแลระบบเป็นผู้เพิ่มบัญชีเจ้าหน้าที่ **ยังไม่ได้สร้างบัญชีหรือกำหนดรหัสผ่านให้คุณ**

ใบรับรอง HTTPS ที่สร้างอัตโนมัติเป็นใบรับรองทดสอบ เบราว์เซอร์อาจแจ้งว่าไม่เชื่อถือ ก่อนใช้จริงให้ฝ่ายไอทีจัดใบรับรองที่ตรงกับชื่อเซิร์ฟเวอร์และเชื่อถือได้บนเครื่องของหน่วยงาน

## เปิดให้ใช้ในเครือข่ายโรงพยาบาล

ค่าเริ่มต้นฟังเฉพาะ `127.0.0.1:8443` เพื่อให้ทดลองได้ก่อน **เครื่องอื่นยังเชื่อมต่อไม่ได้** ต้องทราบชื่อหรือ IP คงที่ของเซิร์ฟเวอร์ และช่วง IP ของทุกวงที่จะใช้งาน ก่อนเปิดใช้จริง

เมื่อมีหลายวง LAN จุดที่ตัดสินผลไม่ใช่แค่การเปิดพอร์ต แต่เป็นวิธีที่เอเจนต์ใช้หาเซิร์ฟเวอร์

- เปิด `LANonly` เอเจนต์จะได้ค่า `MeshServer=local` คือค้นหาเซิร์ฟเวอร์ด้วย multicast ซึ่งปกติไม่ข้าม VLAN เครื่องต่างวงจะติดตั้งเอเจนต์แล้วไม่ปรากฏในระบบ
- ตั้ง `settings.cert` เป็นชื่อ DNS หรือ IP คงที่ของเซิร์ฟเวอร์ เอเจนต์จะได้ที่อยู่ตรง `wss://<ชื่อเซิร์ฟเวอร์>:8443/agent.ashx` และข้ามวงได้ถ้าเส้นทางเครือข่ายและ DNS ถึงกัน
- ชื่อใน `settings.cert` **ต้องมีจุด** ถ้าไม่มีจุด เซิร์ฟเวอร์จะถอยกลับไปโหมด LAN-only เองโดยไม่แจ้งเตือน

`hospital/config.lan.example.json` คือตัวอย่างสำหรับหลายวง กำหนด `cert` ไว้ ไม่กำหนด `portBind` (ฟังทุกการ์ดเครือข่าย) และใส่ช่วง IP หลายรายการ **ค่าทุกค่าในไฟล์นั้นเป็นค่าสมมติ** ต้องเปลี่ยนให้ตรงกับหน่วยงานก่อนใช้

หยุดเซิร์ฟเวอร์ด้วย Ctrl+C แก้ `.local/scp-remote/config.json` แล้วตรวจด้วย

```powershell
npm run check:config
```

คำสั่งนี้อ่านอย่างเดียว ไม่แก้ไฟล์และไม่ติดต่อเครือข่าย จะบอกว่าเอเจนต์จะหาเซิร์ฟเวอร์ด้วยวิธีใด เปิดให้วงใดแล้วบ้าง และเตือนเมื่อใส่ช่วง IP ของวงอื่นไว้ทั้งที่ยังใช้ multicast อยู่

กำหนดไฟร์วอลล์เซิร์ฟเวอร์ให้อนุญาต TCP 8443 เฉพาะเครือข่ายที่ต้องใช้ ไม่ทำ port forwarding จากอินเทอร์เน็ต `userAllowedIP`/`agentAllowedIP` เป็นการกรองในระดับแอปพลิเคชัน ไม่ใช่ไฟร์วอลล์ และ `LANonly` ไม่ใช่ขอบเขตความปลอดภัย

ค่าตั้งต้นปิด self-update, WebRTC และปลั๊กอิน ไม่ได้เปิดบริการอีเมล SMS หรือสำรองข้อมูลไปยังคลาวด์ ฟอนต์โหลดจากเครื่องเซิร์ฟเวอร์ การติดตั้งแพ็กเกจครั้งแรกยังต้องใช้อินเทอร์เน็ตหรือแหล่งแพ็กเกจภายในที่เตรียมไว้ การจำกัดการออกอินเทอร์เน็ตทั้งระบบต้องกำหนดที่ไฟร์วอลล์ของหน่วยงานเพิ่มเติม

ตั้งค่าให้ถามความยินยอมก่อนเข้าถึงหน้าจอ เทอร์มินัล และไฟล์ พร้อมแจ้งเตือนการรีโมตหน้าจอ โดยไม่ยอมรับอัตโนมัติเมื่อหมดเวลา ปรับได้ใน `domains[""].userConsentFlags` และ `consentMessages` ให้ตรงกับขั้นตอนงานของโรงพยาบาล

## ติดตั้งเป็นบริการของ Windows

ให้ SCP-Remote เริ่มทำงานเองเมื่อเปิดเครื่อง แทนการเปิดหน้าต่าง `Start-SCP-Remote.cmd` ค้างไว้

ปิดเซิร์ฟเวอร์ที่เปิดค้างอยู่ด้วย Ctrl+C ก่อน แล้วเปิด **PowerShell แบบ Run as administrator** ในโฟลเดอร์โครงการ

```powershell
npm run build:hospital
npm run service:install
```

คำสั่งอื่น: `npm run service:start`, `service:stop`, `service:restart` และ `service:uninstall` ซึ่งถอนบริการออกโดยไม่ลบข้อมูลใน `.local/scp-remote/`

บริการชื่อ **SCP-Remote** ใช้ข้อมูลชุดเดียวกับ `npm run start:hospital` คือ `.local/scp-remote/` บัญชีและอุปกรณ์จึงต่อเนื่องกัน หากหน้าไทยยังไม่ได้ build ใหม่ คำสั่ง install/start/restart จะหยุดและบอกชื่อเทมเพลตที่ค้างไว้

ติดตั้งบริการนี้บน `DESKTOP-TA7KT4Q` แล้ว สถานะ Running เริ่มอัตโนมัติเมื่อเปิดเครื่อง ตัวเริ่มระบบของบริการ (`scripts/service-runner.js`) ยังทำหน้าที่ก๊อปไฟล์สำรองไปอีกไดรฟ์ทุกวันเวลา 02:30 ด้วย ดูหัวข้อ **สำรองข้อมูล**

## ภาษาและการปรับหน้าตา

- ชื่อที่แสดง: **SCP-Remote** ทั้งหน้าเว็บและตัวเอเจนต์บนเครื่องลูก คงชื่อ MeshCentral ไว้เฉพาะในลิขสิทธิ์ เครดิตต้นฉบับ และคอมเมนต์ในโค้ด
- เอเจนต์บนเครื่องลูกติดตั้งที่ `C:\Program Files\SCP-Remote\scpremote.exe` ชื่อบริการ `scpremoteagent` ตั้งค่าที่ `domains[""].agentCustomization`
- เครื่องที่ติดตั้งก่อนเปลี่ยนชื่อจะยังใช้ชื่อเดิม ตัวติดตั้งรู้จักทั้งสองชื่อจึงไม่ติดตั้งซ้ำ ถ้าต้องการให้เปลี่ยนชื่อต้องถอนแล้วติดตั้งใหม่
- รองรับหน้าเว็บไทยและอังกฤษเท่านั้น ภาษาอื่นที่ส่งมาจะใช้ไทยแทน ส่วนรหัสภูมิภาค `en-US`, `en-GB`, `th-TH` จะใช้ภาษาหลักที่ตรงกัน
- คำแปลดูแลใน `hospital/th.json` โดยใช้ข้อความอังกฤษเป็นคีย์ จึงไม่ผูกกับลำดับแถวต้นฉบับ
- `hospital/retained-en.json` ระบุข้อความที่คงเดิม เช่น ชื่อผลิตภัณฑ์ ชื่อภาษาเก่าที่ไม่ได้แสดงเป็นตัวเลือก คำสั่ง รหัสทางเทคนิค ตัวเลข และข้อความใบอนุญาต
- มีคำแปล 2,619 รายการ รวมข้อความเฉพาะโรงพยาบาล 2 รายการ ครอบคลุมข้อความที่เครื่องมือแปลดึงได้จากหน้าเว็บและอีเมลในชุดนี้ โดยชื่อและข้อความที่ระบุไว้ในรายการคงเดิมไม่ถูกแปล
- ฟอนต์ Sarabun แบบ Regular, SemiBold และ Bold อยู่ใน `public/fonts/sarabun/` ไม่เรียก Google Fonts ตอนเปิดหน้าเว็บ เก็บ OFL ไว้กับฟอนต์ ส่วนเทอร์มินัลและตัวแก้ไขโค้ดยังคงฟอนต์ monospace
- ธีมอยู่ใน `public/styles/scp-remote.css` โลโก้โรงพยาบาลเก็บต้นฉบับไว้ที่ `hospital/brand/logo.png` และสำเนาที่ใช้งานอยู่ที่ `public/images/scp-logo.png` (เว็บ) กับ `hospital/client-setup/logo.png` (ตัวติดตั้ง) เปลี่ยนโลโก้ให้แทนที่ทั้งสามไฟล์
- หลังแก้คำแปลหรือเทมเพลต ให้รัน `npm run build:hospital` ใหม่ ได้หน้าไทย 24 หน้า ทั้งแบบปกติและแบบย่อ รวมถึงอีเมลไทย โดยใช้ตัวแปลเดิมของ MeshCentral หากลืม build ใหม่ `npm run start:hospital` จะไม่เปิดเซิร์ฟเวอร์ แต่แจ้งชื่อเทมเพลตที่ค้างไว้แทน เพื่อไม่ให้หน้าไทยที่ผู้ใช้เห็นเป็นเวอร์ชันเก่า
- หน้าเข้าสู่ระบบบนมือถือใช้เทมเพลตคนละไฟล์กับบนเดสก์ท็อป ลิงก์สลับภาษาจึงวางไว้ในคอลัมน์ล็อกอินแทนแถบบน และมีการตรวจแยกทั้งสองแบบ

ซอฟต์แวร์เอเจนต์และเครื่องมือ native ยังคงชื่อและไบนารีของโครงการเดิม การแปลชุดนี้มุ่งที่เว็บและอีเมล ยังไม่ได้สร้างไบนารีเอเจนต์ชื่อ SCP-Remote ขึ้นใหม่

## สำรองข้อมูล

เซิร์ฟเวอร์สำรองตัวเองทุกวันตอนตี 2 เก็บไว้ 30 วัน ลงที่ `autoBackup.backupPath` ซึ่งตอนนี้คือ `F:/EX/scp-remote-backups` ไฟล์สำรองมีทั้งฐานข้อมูล ใบรับรอง และบัญชีผู้ใช้

ปัญหาคือทั้งเซิร์ฟเวอร์และไฟล์สำรองอยู่ในเครื่องเดียวกัน ดิสก์ลูกเดียวเสียคือหายทั้งคู่ จึงมีคำสั่งก๊อปไปอีกไดรฟ์

```
npm run backup:copy -- H:\SCP-Remote-Backups
```

คำสั่งนี้ก๊อปเฉพาะไฟล์ที่ยังไม่มีหรือเปลี่ยนไป ลบสำเนาที่เก่ากว่าอายุที่เซิร์ฟเวอร์ตั้งไว้ และแตะเฉพาะไฟล์ชื่อ `meshcentral-autobackup-*.zip` เท่านั้น ไม่ยุ่งกับไฟล์อื่นในโฟลเดอร์ปลายทาง

คำสั่งนี้ก๊อป `signedagents/` ไปด้วย ซึ่งการสำรองปกติข้ามไว้ตาม `backupSkipFoldersGlob` โฟลเดอร์นั้นคือไฟล์เอเจนต์ที่เซิร์ฟเวอร์เซ็นแล้วและใช้เสิร์ฟให้คนที่กดติดตั้ง ถ้าหายไปจะเพิ่มเครื่องใหม่ผ่านหน้าเว็บไม่ได้

**ไม่ต้องตั้ง scheduled task** บริการ SCP-Remote ก๊อปให้เองทุกวันเวลา 02:30 (หลังการสำรองตอนตี 2) กำหนดปลายทางที่ `settings.autoBackup.scpBackupCopyPath` ในไฟล์ตั้งค่า

```json
"autoBackup": {
  "backupPath": "F:/EX/scp-remote-backups",
  "scpBackupCopyPath": "H:\\SCP-Remote-Backups"
}
```

ถ้าไม่ใส่ `scpBackupCopyPath` ระบบจะไม่ก๊อปอะไรเลยและไม่ฟ้อง error

ทำแบบนี้แทน scheduled task เพราะไม่ต้องติดตั้งอะไรเพิ่ม ทำงานแม้ไม่มีใครล็อกอินอยู่ เริ่มและหยุดพร้อมบริการ และไม่มีใครลบทิ้งโดยไม่รู้ตัว ถ้าเครื่องปิดอยู่ตอน 02:30 จะก๊อปให้อีกครั้ง 5 นาทีหลังเปิดเครื่อง

ตรวจว่าทำงานหรือยังได้จาก `scripts/daemon/scpremote.out.log` จะมีบรรทัดขึ้นต้นด้วย `[backup-copy]` บอกว่าตั้งเวลาไว้แล้ว และบอกผลทุกครั้งที่ก๊อป

สั่งก๊อปเดี๋ยวนี้เองก็ได้ ไม่ต้องรอถึงเวลา

### ซ้อมกู้คืน

ไฟล์สำรองที่ไม่เคยลองกู้ ไม่ใช่ไฟล์สำรอง เป็นแค่ความเชื่อ ตรวจได้ด้วยคำสั่งเดียว

```
npm run drill:restore
```

สคริปต์จะเอาไฟล์สำรองล่าสุดมาแตก ตรวจว่ามีใบรับรองและฐานข้อมูลครบ เปิดเซิร์ฟเวอร์จำลองขึ้นมาบนพอร์ตว่าง ๆ ที่**ฟังเฉพาะ 127.0.0.1 เครื่องอื่นและเอเจนต์เข้าไม่ได้** ตรวจว่าหน้าเข้าสู่ระบบตอบจริง นับบัญชี กลุ่ม และเครื่องที่กู้ได้เทียบกับของจริง แล้วปิดและลบทิ้ง **ไม่แตะเซิร์ฟเวอร์ที่ใช้งานอยู่เลย**

ซ้อมครั้งล่าสุดผ่าน ได้บัญชี 1 · กลุ่ม 3 · เครื่อง 3 ครบเท่าของจริง

**ยังไม่ใช่การสำรองนอกสถานที่** ไดรฟ์ทุกลูกของเครื่องนี้เป็นดิสก์ในเครื่องเดียวกันหมด ไม่มีไดรฟ์เครือข่าย สิ่งที่ทำได้ตอนนี้จึงกันได้แค่ดิสก์เสีย ไม่ได้กันไฟไหม้ น้ำท่วม เครื่องถูกขโมย หรือแรนซัมแวร์ที่เข้ารหัสทุกไดรฟ์ที่มองเห็น ควรมีสำเนาที่ออกไปนอกอาคารเพิ่ม เช่น NAS คนละตึก หรือฮาร์ดดิสก์ที่สลับกันถือกลับ

## ตรวจสอบ

```powershell
npm run build:hospital
npm run test:hospital
npm run check:config
# เปิดเซิร์ฟเวอร์ด้วย start:hospital ในอีกหน้าต่างก่อนคำสั่งนี้
npm run check:hospital
```

ตรวจตัวแปรในคำแปล, ภาษา/รหัสภูมิภาค, ลิงก์สลับภาษาทั้งบนเดสก์ท็อปและมือถือ, ความสดใหม่ของหน้าไทยเทียบกับเทมเพลตต้นทาง, JavaScript ในหน้าไทยปกติและแบบย่อ 48 ไฟล์, การตอบ HTTP, การจำภาษาผ่านเซสชัน และการโหลดฟอนต์/ภาพ/CSS ภายในแล้ว ตรวจ startup ของหน้าเข้าสู่ระบบด้วย DOM จำลอง ทั้งหน้าเดสก์ท็อปและหน้าที่เซิร์ฟเวอร์ส่งให้เครื่องมือถือ แล้วไม่พบ JavaScript error และได้ฟอนต์ Sarabun

**ยังไม่ได้ตรวจภาพหน้าจอในเบราว์เซอร์จริง และยังไม่ได้ทดสอบรีโมตกับเครื่องปลายทางจริง** การตรวจทั้งหมดข้างต้นใช้ DOM จำลองและการเรียก HTTP ไม่ใช่การมองด้วยตา ขั้นตอนทดสอบกับเครื่องจริงอยู่ในหัวข้อถัดไป

กล่องที่เด้งขึ้นบนเครื่องปลายทางก่อนเข้าใช้งาน ปรับเป็นภาษาไทยและสีของโรงพยาบาลแล้ว

## ดูภาพหน้าจอหลายเครื่องพร้อมกัน

ในหน้า **แดชบอร์ด** มีปุ่ม **เปิดดูภาพหน้าจอ** อยู่มุมขวาบน กดแล้วแต่ละแถวจะมีภาพหน้าจอเล็ก ๆ ของเครื่องนั้นขึ้นมา คลิกที่ภาพเพื่อเข้าควบคุมเต็มจอ หรือกดปุ่มมุมขวาบนของภาพเพื่อบันทึกภาพนั้นเป็นไฟล์ `.png` เก็บไว้

ภาพที่วิ่งอยู่ตลอดตั้งใจให้เบา คือ WebP คุณภาพ 40 ย่อเหลือ 37.5% ส่งใหม่ทุก 1 วินาที (`liveSettings` ใน `public/scripts/scp-dashboard.js`) พอเห็นว่าเครื่องกำลังทำอะไรอยู่ และคมพอบนจอความละเอียดสูง

แต่ **ตอนกดบันทึกภาพจะได้ความละเอียดเต็ม** ระบบจะขอภาพจากเครื่องนั้นใหม่หนึ่งเฟรมที่ขนาดจริง 100% คุณภาพ 100 (`liveCapture`) รอจนภาพมาครบ บันทึกเป็นไฟล์ แล้วกลับไปใช้ภาพเล็กแบบเดิมทันที ไฟล์ที่ได้จึงอ่านออกใช้เป็นหลักฐานได้ โดยไม่ต้องแบกภาพความละเอียดสูงไว้ตลอดเวลา ชื่อไฟล์เป็น `SCP-Remote_<ห้อง>_<ชื่อเครื่อง>_<วันเวลา>.png` เก็บรวมกันไว้ในโฟลเดอร์เดียวก็อ่านเป็นบันทึกได้เลย

| ข้อกำหนด | ค่า | เหตุผล |
| --- | --- | --- |
| ดูได้ครั้งละกี่เครื่อง | 12 (`liveLimit`) | แต่ละภาพคือการเชื่อมต่อจริงหนึ่งชุด เปิดพร้อมกันทั้งโรงพยาบาลจะกินทั้งเครือข่ายและเครื่องเซิร์ฟเวอร์ |
| เริ่มเมื่อไร | ต่อเมื่อกดปุ่มเท่านั้น | ไม่จำค่าไว้ข้ามการเปิดหน้าใหม่ จะได้ไม่เผลอเปิดดูค้างไว้โดยไม่รู้ตัว |
| หยุดเมื่อไร | ปิดปุ่ม ออกจากหน้าแดชบอร์ด เครื่องปลายทางปิด หรือหลุดการเชื่อมต่อ | ไม่ให้มีการดูหน้าจอค้างอยู่ทั้งที่ไม่มีคนดู |
| สั่งงานเครื่องปลายทางได้ไหม | ไม่ได้ | ภาพเหล่านี้ไม่ผูกเมาส์และคีย์บอร์ดไว้เลย ดูได้อย่างเดียว ถ้าจะสั่งงานต้องคลิกเข้าหน้าควบคุมเต็มจอ |
| ถ้าเครื่องปลายทางปฏิเสธ | ขึ้นปุ่ม **ลองใหม่** รอไว้ | ไม่ต่อซ้ำเองเป็นรอบ ๆ เพราะจะกลายเป็นเด้งกล่องขออนุญาตใส่ผู้ใช้ไม่หยุด |
| ถ้าขอภาพเต็มแล้วไม่มา | ยอมแพ้ใน 6 วินาที บันทึกภาพเท่าที่มี แล้วคืนค่าเดิม | ไม่ปล่อยให้ค้างอยู่ที่ความละเอียดสูงจนกินแบนด์วิดท์ |

ใต้ปุ่มจะมีบรรทัดบอกว่า **เครื่องที่ถูกดูจะเห็นอะไร** ซึ่งอ่านจากค่า `userConsentFlags` ของเซิร์ฟเวอร์จริง ไม่ได้เขียนตายไว้ และถ้าตั้งไว้หลายอย่างพร้อมกันก็จะบอกครบทุกอย่าง ไม่ใช่บอกแค่อันแรก

**ค่าที่ใช้อยู่จริงตอนนี้** แยกการ **ดูภาพ** ออกจากการ **คุมเครื่อง** คนละแบบ

| ทำอะไร | เครื่องที่ถูกดูจะเห็น |
| --- | --- |
| ดูภาพหน้าจอ (การ์ดในแดชบอร์ด และมุมมองจอสตรีม) | ไม่มีกล่องถาม ภาพขึ้นเลย · ขึ้นแจ้งเตือนตอนเริ่ม · **ไม่มีแถบค้างบนจอ** |
| รีโมตเต็มจอ คุมเมาส์คีย์บอร์ดได้ | **ถามก่อนเหมือนเดิม** ภาพขึ้นเมื่อผู้ใช้กดอนุญาตเท่านั้น |
| หน้าต่างคำสั่ง / เข้าถึงไฟล์ / รีจิสทรี | ถามก่อนเหมือนเดิม |

แถบค้างบนจอ (`desktopprivacybar`) ถูก **ปิดไว้ตามที่ผู้ดูแลสั่ง** สิ่งที่เหลือบอกผู้ใช้ว่ากำลังถูกดูจึงมีแค่การแจ้งเตือนตอนเริ่มเท่านั้น เปิดกลับได้โดยตั้ง `desktopprivacybar: true` ใน `userConsentFlags` แล้วรีสตาร์ต ข้อความบนแถบแก้ได้ที่คีย์ `privacyBar` ใน `agents/modules_meshcore/coretranslations.json`

รายละเอียดหน้าต่างขออนุญาตบนเครื่องลูก อยู่ใน [หน้าต่างขออนุญาตและหน้าดูหลายเครื่อง](CONSENT-AND-LIVE-SCREENS.md)

### ทำไมถึงลดได้เฉพาะการดูภาพ

ธงยินยอมของ MeshCentral เป็นแบบ **บวกกันอย่างเดียว** (โดเมน | กลุ่ม | เครื่อง | ผู้ใช้) ตั้งค่าธรรมดาจึงแยกไม่ได้ว่าการเชื่อมต่อไหนต้องถามหรือไม่ต้องถาม ระบบนี้จึงเพิ่มเส้นทางหนึ่งเข้าไป และบังคับไว้ 3 ชั้น

1. เบราว์เซอร์ที่จะเปิดแค่ภาพ ส่ง `viewonly: true` มากับคำขอเปิดท่อ (`public/scripts/agent-redir-ws-0.1.1.js`)
2. เซิร์ฟเวอร์ตั้ง `desktopviewonly` ให้ท่อนั้น และตัดบิตกล่องขออนุญาตของหน้าจอ (บิต 8) ออก **เฉพาะเมื่อโดเมนเปิด `desktopViewOnlyNoPrompt`** ทั้งสองอย่างเขียนอยู่ในเงื่อนไขเดียวกันที่ `applyViewOnlyConsent` ใน `meshuser.js`
3. เอเจนต์บนเครื่องลูกรับเฉพาะแพ็กเก็ตที่เป็นการตั้งค่าการแสดงผล (`agents/modules_meshcore/scp-viewonly.js`) เมาส์ คีย์บอร์ด Ctrl+Alt+Del คำสั่งล็อกเครื่อง คำสั่งที่ไม่รู้จัก และแพ็กเก็ตผิดรูป ถูกทิ้งทั้งหมด

จุดสำคัญคือข้อ 2 กับ 3 ผูกกับธงตัวเดียวกันที่ส่งไปให้เอเจนต์ ใครก็ตามที่ขอให้ไม่ต้องถาม จะเสียความสามารถในการสั่งงานเครื่องนั้นไปพร้อมกันเสมอ และการบังคับอยู่ที่เครื่องลูก ไม่ใช่ที่เบราว์เซอร์ เบราว์เซอร์ที่ถูกดัดแปลงจึงโกงไม่ได้

ถ้าเปิด `desktopMultiplex` เส้นทางนี้จะไม่ทำงาน เพราะภาพหนึ่งชุดถูกแชร์กันหลายคน การลดสิทธิ์ให้คนดูภาพจะไปตัดสิทธิ์คนที่กำลังคุมเครื่องอยู่ด้วย ระบบจึงคงการขออนุญาตเดิมไว้ทั้งหมดในกรณีนั้น และบังคับดูอย่างเดียวแยกรายคนที่ตัว multiplexor แทน

เทสต์ที่คุมเรื่องนี้อยู่ที่ `hospital/tests/viewonly.test.js` และ `hospital/tests/scp-viewonly-packets.test.js`

ถ้าจะให้กลับไปถามทุกครั้งเหมือนเดิม ลบ `desktopViewOnlyNoPrompt` ออกจากไฟล์ตั้งค่าแล้วรีสตาร์ต การดูภาพจะกลับไปถามก่อนทันที

ถ้าตั้งจนเครื่องปลายทางไม่เห็นอะไรเลย (ปิด `desktopnotify` ด้วย) หน้าแดชบอร์ดจะเตือนไว้ให้ การดูหน้าจอเครื่องที่เจ้าหน้าที่ใช้อยู่ถือเป็นการเก็บข้อมูลส่วนบุคคลตาม พ.ร.บ.คุ้มครองข้อมูลส่วนบุคคล จึงควรแจ้งเจ้าหน้าที่เป็นลายลักษณ์อักษรไว้ก่อนว่าหน้าจอของเครื่องโรงพยาบาลอาจถูกดูเพื่อการดูแลระบบ และเก็บประกาศนั้นไว้เป็นหลักฐาน ตัวเซิร์ฟเวอร์บันทึกทุกครั้งที่มีการเปิดดูหน้าจออยู่แล้วในหน้า **เหตุการณ์** ว่าใครดูเครื่องใดเมื่อไร

### มุมมองจอสตรีมในหน้ารายการอุปกรณ์

ปุ่มที่ 3 และ 4 มุมขวาบนของหน้า **อุปกรณ์ของฉัน** คือมุมมองจอสตรีมที่ติดมากับ MeshCentral อยู่แล้ว แสดงภาพใหญ่กว่าแดชบอร์ดและเรียงเต็มหน้า ใช้คู่กันได้ ต่างกันตรงที่แดชบอร์ดวางภาพไว้คู่กับสถานะ ผู้ใช้ที่ล็อกอิน และสิ่งที่ต้องดูแลของเครื่องนั้นในแถวเดียวกัน

ของเดิมใช้งานยากอยู่สองเรื่อง แก้แล้วทั้งคู่

- ปุ่มทั้งสองขึ้นคำอธิบายเหมือนกันว่า "Desktops" ไม่มีอะไรบอกว่าต่างกันอย่างไร ตอนนี้เป็น **จอสตรีมทุกเครื่อง ขนาดเท่ากัน** กับ **จอสตรีมทุกเครื่อง**
- ช่อง **ต่อภาพอัตโนมัติ** ถูกบังคับปิดทุกครั้งที่วาดหน้ารายการแบบอื่น ติ๊กไว้ก็หลุดทุกรอบ พอกดเข้ามุมมองนี้จึงเจอกล่องดำเขียนว่าตัดการเชื่อมต่อเต็มหน้า เหมือนฟีเจอร์เสีย ตอนนี้จำค่าไว้แล้วและเปิดไว้ให้ตั้งแต่ต้น

ความละเอียดเริ่มต้นของมุมมองนี้เดิมคือคุณภาพ 20 ย่อเหลือ 12.5% ซึ่งหยาบเกินกว่าจะดูออกว่าเครื่องทำอะไรอยู่ ปรับเป็นคุณภาพ 60 ย่อเหลือ 50% ส่งใหม่ทุก 0.4 วินาที และมีการยกค่าให้เบราว์เซอร์ที่เคยใช้มาก่อนครั้งเดียว (`scpMultiDesktopSharp1`) ใครที่ตั้งค่าเองไว้ดีกว่านั้นอยู่แล้วจะไม่ถูกแตะ ปรับเองได้ที่ปุ่ม **ตั้งค่า** ในแถบเครื่องมือของมุมมองนั้น

## ชุดติดตั้งสำหรับเครื่องลูก

`hospital/client-setup/SCP-Remote-Setup.exe` คือตัวติดตั้งสำหรับเครื่องผู้ใช้ เป็นไฟล์เดียวจบ กดถัดไปทีละหน้า มีหน้าให้ติ๊กยินยอมและช่องตั้งชื่อเครื่องที่จะใช้เป็นชื่อบนระบบ โลโก้กับไอคอนฝังอยู่ในไฟล์แล้ว และขอสิทธิ์ผู้ดูแลเครื่องเองเมื่อเปิด ขั้นตอนเตรียมและแจกอยู่ใน [client-setup/README.md](client-setup/README.md)

ไฟล์เอเจนต์ของกลุ่มอุปกรณ์ถูกฝังอยู่ในไฟล์นี้ด้วย จึงก๊อปไปเครื่องลูกไฟล์เดียวได้ ไม่ต้องมีไฟล์อื่นวางคู่ สร้างใหม่ด้วย `npm run build:setup-exe` เมื่อเปลี่ยนไฟล์เอเจนต์ใน `client-setup/agents/` แก้ข้อความใน `client-setup/src/Setup.cs` หรือเปลี่ยนโลโก้ ใช้ตัวคอมไพล์ที่ติดมากับ Windows ไม่ต้องติดตั้งเครื่องมือเพิ่ม

วิธีที่แนะนำคือสร้างกลุ่มอุปกรณ์ไว้กลุ่มเดียวชื่อ **เครื่องใหม่** ดาวน์โหลดตัวติดตั้งของกลุ่มนั้นครั้งเดียว แล้วใช้ชุดเดียวกันกับเครื่องลูกทุกเครื่อง เครื่องที่ติดตั้งแล้วจะเข้ามารออยู่ในกลุ่มนี้พร้อม IP และรายละเอียดเครื่อง ผู้ดูแลระบบค่อยเลือกหลายเครื่องพร้อมกันแล้วสั่ง **ย้ายไปกลุ่มอุปกรณ์** ไปยังกลุ่มจริงทีหลัง โดยไม่ต้องแตะเครื่องลูกอีก

เครื่องลูกจึงมีงานเดียวคือกดติดตั้ง และฝ่ายไอทีไม่ต้องรู้ IP ของเครื่องลูกล่วงหน้า เพราะเอเจนต์เป็นฝ่ายวิ่งเข้ามาหาเซิร์ฟเวอร์เอง ต่างจาก VNC ที่ผู้ดูแลต้องต่อไปหาแต่ละเครื่องตาม IP

รหัสที่กรอกถูกเขียนเป็น `~ServerName:` ในไฟล์ tag ของเอเจนต์ และเซิร์ฟเวอร์นำไปตั้งเป็นชื่ออุปกรณ์ตามค่า `domains[""].agentTag` ที่เปิดไว้ กรอกภาษาไทยและความยาวเท่าใดก็ได้ เพราะรหัสนี้เป็นเพียงชื่อที่แสดง ไม่ได้ใช้ยืนยันตัวตน สิ่งที่ยืนยันว่าเครื่องอยู่กลุ่มใดคือกุญแจที่ฝังมากับตัวติดตั้งอยู่แล้ว

## ทดสอบรีโมตกับเครื่องจริง

ยังไม่ได้ทดสอบขั้นนี้ ทำกับเครื่องทดสอบหนึ่งเครื่องก่อนนำไปใช้กับงานจริงเสมอ

1. สร้างบัญชีผู้ดูแลระบบ ขณะนี้ยังไม่มีบัญชีใดในระบบ เปิดหน้าเข้าสู่ระบบแล้วสร้างบัญชีแรก บัญชีนี้จะเป็นผู้ดูแลระบบโดยอัตโนมัติ หลังจากนั้น `newAccounts: false` จะปิดการสมัครเอง ให้ผู้ดูแลระบบเป็นผู้เพิ่มบัญชีเจ้าหน้าที่

   บัญชีถูกเก็บในไฟล์ `.local/scp-remote/meshcentral.db` บนเครื่องเซิร์ฟเวอร์เท่านั้น ไม่ส่งออกที่ใด รหัสผ่านเก็บเป็นค่าแฮช PBKDF2-SHA384 12,000 รอบ พร้อม salt สุ่ม ไม่ได้เก็บรหัสผ่านจริง

   **ไม่ได้ตั้งค่าอีเมลไว้ จึงไม่มีการรีเซ็ตรหัสผ่านทางอีเมล** ถ้าลืมรหัสผ่านผู้ดูแลระบบ ต้องกู้ที่ตัวเครื่องเซิร์ฟเวอร์ หยุดบริการก่อนแล้วสั่ง

   ```powershell
   npm run service:stop
   node meshcentral.js --datapath .localscp-remote --resetaccount ชื่อผู้ใช้ --pass รหัสผ่านใหม่
   npm run service:start
   ```

   คำสั่งนี้ปลดล็อกบัญชี ตั้งรหัสผ่านใหม่ และปิด 2FA ของบัญชีนั้น จึงต้องจำกัดผู้ที่เข้าถึงเครื่องเซิร์ฟเวอร์และโฟลเดอร์ `.local/scp-remote/` ให้เท่ากับสิทธิ์ผู้ดูแลระบบ
2. เปิดให้เครื่องทดสอบเข้าถึงได้ ตั้ง `settings.cert` เป็น IP คงที่หรือชื่อ DNS ของเซิร์ฟเวอร์ ใส่ช่วง IP ของวงที่เครื่องทดสอบอยู่ใน `userAllowedIP` และ `agentAllowedIP` เปิดไฟร์วอลล์ให้ TCP 8443 เฉพาะวงนั้น แล้วตรวจด้วย `npm run check:config`
3. สร้างกลุ่มอุปกรณ์ในระบบ แล้วดาวน์โหลดตัวติดตั้งเอเจนต์จากหน้ากลุ่มนั้นไปติดตั้งบนเครื่องทดสอบ เครื่องควรขึ้นในรายการภายในเวลาไม่นาน ถ้าไม่ขึ้น ให้ตรวจข้อ 2 ก่อนเสมอ เพราะสาเหตุที่พบบ่อยคือเอเจนต์หาเซิร์ฟเวอร์ไม่พบ ไม่ใช่ตัวเอเจนต์เสีย
4. ตรวจบนเครื่องทดสอบว่า ผู้ใช้ปลายทางเห็นคำขอความยินยอมก่อนเข้าหน้าจอ เทอร์มินัล และไฟล์ เห็นการแจ้งเตือนขณะถูกรีโมต ปฏิเสธได้ และคำขอไม่ถูกยอมรับเองเมื่อหมดเวลา
5. ตรวจสิทธิ์ของบัญชีเจ้าหน้าที่ด้วยบัญชีที่ไม่ใช่ผู้ดูแลระบบ ว่าเห็นและทำได้เฉพาะกลุ่มอุปกรณ์ที่ได้รับมอบหมาย
6. ตรวจการถอนการติดตั้ง ว่าถอนเอเจนต์ออกจากเครื่องทดสอบได้จนสุด

ระหว่างทดสอบ ให้จดว่าเครื่องใดติดตั้งเอเจนต์ไปแล้วบ้าง เพื่อถอนออกให้ครบเมื่อเลิกทดสอบ

## English quick start

SCP-Remote is a hospital-internal customization of MeshCentral 1.2.5. Run `npm ci`, `npm run build:hospital`, then `npm run start:hospital`. Open https://127.0.0.1:8443 and select English. The first account becomes the administrator; public registration is disabled after that account exists.

The default listener and access lists are loopback-only. The hospital runs several LAN segments, so what decides whether a remote machine appears is how its agent finds the server. Set `settings.cert` to the server's fixed DNS name or IP: a name without a dot silently drops the server back to LAN-only mode, where agents only discover it by multicast and do not cross VLANs. Leave `portBind` unset to listen on every interface, list the real CIDRs in `userAllowedIP` and `agentAllowedIP`, configure the host firewall, and install a trusted internal TLS certificate. `npm run check:config` reads the configuration and reports what is still missing, and `hospital/config.lan.example.json` shows the shape with placeholder values. `npm run service:install` registers the SCP-Remote Windows service from an elevated prompt. No service has been installed and no deployment has been performed.

Thai and English are the only UI languages. Sarabun fonts are served locally. After editing a template or a translation, re-run `npm run build:hospital`; `npm run start:hospital` refuses to start while a generated Thai page is older than its template. Remote desktop, terminal, and file access require user consent by default. Native agents retain their upstream identity. Real-browser visual checks and real-device remote-control testing are still required.
