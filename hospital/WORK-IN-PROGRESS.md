## หน้าเหตุการณ์แบบสรุป — Codex รับต่องาน Claude, 13 พฤศจิกายน 2569

- เชื่อม `scp-events.js` และ `scp-events.css` ที่ค้างไว้เข้าหน้าเว็บหลัก: สรุปรีโมตตามเซสชัน ค้นหาเครื่อง/ผู้ใช้/IP กรองรีโมต/เข้าสู่ระบบ/ต้องดู และเปิดบันทึกเดิมได้
- ป้องกันการรวมเหตุการณ์แก้ไขเครื่องที่ไม่เกี่ยวกับรีโมต และไม่ผูกเหตุการณ์เข้ากับเซสชันเมื่อมีหลายเซสชันที่เป็นไปได้ ข้อมูลต้นฉบับยังอยู่ครบ
- ระบุยอดวันนี้ว่าเป็นเฉพาะบันทึกที่โหลด ไม่อ้างว่าเซสชันยังเปิดเมื่อขาดบันทึกจบ ไม่ตีความ loopback ว่าเป็นอินเทอร์เน็ต และใช้คำว่าเปิดช่องทางรับส่งไฟล์แทนการยืนยันว่ามีการส่งไฟล์
- เมื่อสรุปเกิดข้อผิดพลาดจะแสดงรายการเดิม ปรับรายการรายละเอียดให้ใช้แป้นพิมพ์ได้ และแก้ข้อความเตือนในธีมมืด/การตัดบรรทัดบนจอเล็ก
- ตรวจ: เทสต์รวม 745 ผ่าน (หน้าเหตุการณ์ 11), build ไทย/อังกฤษและ HTTP checks ผ่าน ตรวจ Chrome ด้วยข้อมูลจำลอง 390px สว่าง และ 1280px มืด ไม่มีแนวนอนล้น ภาพอยู่ `.local/ui-review/events/` ยังไม่ได้ตรวจหน้าหลังล็อกอินด้วยบัญชีจริง
- เปิดหน้าเหตุการณ์แล้วกด Ctrl+F5 เพื่อโหลดไฟล์ใหม่ ไม่ได้รีสตาร์ตบริการในรอบนี้

## รีโมตไม่หลุด + ใบแจ้งซ่อมเชื่อมรีโมต + บันทึกบนเซิร์ฟเวอร์ (งาน C, E) — Claude, 12–13 พฤศจิกายน 2569

- **ต่อใหม่อัตโนมัติ (`scp-session.js` และสำเนาในโปรแกรม):** เซสชันที่ได้ภาพแล้วหลุดเอง จะต่อใหม่เองสูงสุด 3 ครั้ง (รอ 2, 5, 10 วินาที) ไม่ต่อใหม่ถ้าช่างกดตัดการเชื่อมต่อเอง ผู้ใช้กดปฏิเสธ เครื่องปิด หรือช่างออกจากจอรีโมตแล้ว ปุ่ม "ลองใหม่" เริ่มนับใหม่ เครื่องปลายทางจะถูกถามอนุญาตอีกครั้งทุกครั้งที่ต่อใหม่
- **บันทึกสาเหตุที่รีโมตไม่สำเร็จ:** คำสั่ง `sessionLog` / `sessionFailures` ใน `operations.js` เก็บ 50 รายการล่าสุดต่อเครื่อง ดูได้ที่เมนู ดูแลเครื่อง → "รีโมตที่ต่อไม่ได้" และในประวัติเครื่อง **บันทึกเฉพาะการรีโมตผ่านเว็บ** หน้าต่างของโปรแกรม SCP-Remote ไม่มีช่องทางส่งข้อมูลนี้

## โปรแกรม SCP-Remote อัปเดตตัวเอง (งาน D) + หน้ารีโมตบนเว็บ — Claude, 12 พฤศจิกายน 2569

- **อัปเดตอัตโนมัติ:** โปรแกรมเริ่มที่ `hospital/desktop-app/boot.js` ซึ่งถามเซิร์ฟเวอร์ที่ `/app-update/manifest.json` (ผ่านใบรับรองที่ปักหมุดใน `server.json`) ตอนเปิดและทุก 4 ชั่วโมง รุ่นใหม่ถูกดาวน์โหลดไปไว้ที่ `%APPDATA%/SCP-Remote/app-update/current` ตรวจ SHA-256 ทุกไฟล์ แล้วถามให้เริ่มโปรแกรมใหม่ (ไม่ถามขณะมีหน้าต่างรีโมตเปิดอยู่) ไฟล์ที่ติดตั้งไว้ไม่ถูกแก้ รุ่นที่เปิดไม่ขึ้นถูกย้ายไป `failed` แล้วใช้รุ่นที่ติดตั้ง ตรรกะอยู่ใน `update-core.js` คู่มืออยู่ท้าย `DESKTOP-APP.md`
- **ออกรุ่นใหม่:** แก้โค้ด → เพิ่ม `version` ใน `hospital/desktop-app/package.json` → `cd hospital/desktop-app && npm run publish-update` ไม่ต้องรีสตาร์ตเซิร์ฟเวอร์ **ถอนรุ่นเสีย:** ตั้ง `version` กลับเป็นรุ่นที่ติดตั้งอยู่แล้ว publish อีกครั้ง
- **ตัวติดตั้ง:** `npm run installer` (electron-builder 25.1.8 ผ่าน npx ตั้งค่าใน `installer.json`) ได้ `release/installer/SCP-Remote-Full-Setup-1.2.0.exe` SHA-256 `00a4291943524712404f3bdf230da037c8d2d5d247d1f394368d5f50455a8a98` ตัวติดตั้ง 1.1.0 เดิมสร้างด้วย electron-builder เหมือนกันแต่ไม่มีการตั้งค่าเก็บไว้ในโครงการ ข้างในคือโปรแกรม 0.4.3 ไม่มีตัวอัปเดต **ยังไม่ได้ยืนยันว่า 1.2.0 ติดตั้งทับ 1.1.0 เป็นรายการเดียวกัน** (ขึ้นกับ appId ที่ใช้ตอนสร้าง 1.1.0 ซึ่งไม่ทราบ)
- **ทดสอบแล้ว:** เทสต์ 651 ผ่าน และรัน `boot.js` ใน Electron จริงกับเซิร์ฟเวอร์จำลอง 9 กรณีผ่าน (ดาวน์โหลด, ใช้รุ่นใหม่, ไฟล์ถูกแก้, รุ่นเสียถอยกลับและไม่โหลดซ้ำ, ถอนรุ่น, ใบรับรองผิด) **ยังไม่ได้เปิดโปรแกรม 1.2.0 ตัวจริงบนเครื่องใด และยังไม่ได้ติดตั้งบนเครื่องหัวหน้า**
- **โปรแกรมรุ่นเก่าที่ติดตั้งไปแล้ว:** `public/scripts/scp-app-compat.js` (โหลดใน `sharing.handlebars`) เปลี่ยนคำขอ WEBP 100 ที่รุ่นเก่าล็อกไว้เป็น PNG ให้ รุ่นใหม่ตั้ง `window.scpAppQualityChooser` เพื่อไม่ถูกแตะ
- **เว็บ (ใช้งานจริงแล้ว):** เมนู "รีโมต" เป็นปุ่มแรกในแถบซ้าย (ตารางรูปจอคอม ค้นหา เชื่อมต่อ) · แผง "เครื่องใหม่ รอจัดเข้าหน่วยงาน" พร้อมปุ่มย้าย (กลุ่ม ทดสอบ) · เอา "เพิ่มเครื่อง" ออกจากเมนูดูแลเครื่อง · จอรีโมตเต็มหน้าต่าง แผงเครื่องมือซ้ายพับไว้ แถบควบคุมอยู่ในแถบบน ไม่มีปุ่มเต็มหน้าจอ · ย้อนกลับ/ตัดการเชื่อมต่อกลับไปหน้าที่กดมา · แท็บประเมินสภาพเครื่องไม่ทับเมนูซ้าย
- **รหัส admin:** รีเซ็ตเมื่อ 12 พ.ย. แล้วผู้ดูแลเปลี่ยนเป็นรหัสของตัวเองในวันเดียวกัน (ผู้ดูแลแจ้ง) ยังไม่ได้เปิด 2FA

| ไฟร์วอลล์ขาเข้า | **ปิดสนิททุกพอร์ต** — tunnel ต่อออก ไม่มีใครต่อเข้า |

แต่ชุดปรับคุณภาพอัตโนมัติที่เพิ่มมาใน `a85ab44` ตั้งโปรไฟล์ "คมชัด" เป็น `[2,90,1024,50]` — เลข `2` คือ **PNG** และ [scp-session.js](../public/scripts/scp-session.js) สั่งโปรไฟล์นี้ทันทีที่ได้ภาพแรกของทุกเซสชัน **WEBP จึงอยู่ได้แค่ไม่กี่เฟรมแล้วโดนสลับเป็น PNG ตลอดเซสชัน** โดยไม่มีอะไรฟ้อง เพราะโค้ดสองส่วนไม่เคยเจอกัน

แก้ให้ทุกขั้นของบันไดอยู่บน WEBP แล้ว และ "คมชัด" = `[4,100,1024,50]` ตรงกับค่าตั้งต้นของหน้าเว็บพอดี **มีเทสต์ตรึงค่าไว้แล้ว** รวมถึงเทสต์ที่ตรวจว่าบันไดกับค่าตั้งต้นต้องไม่ขัดกัน

**บทเรียน:** โมดูลที่เขียนมาเพื่อเรื่องหนึ่ง (ปรับคุณภาพ) เผลอพลิกการตัดสินใจของอีกเรื่อง (เลือก encoding) ได้ ถ้าไม่มีเทสต์ตรึงค่าที่ตั้งใจไว้

### ⚠️ แอป Desktop มีสำเนาโค้ดของตัวเอง — แก้ฝั่งเว็บอย่างเดียวไม่พอ

พบตอนแก้ WEBP: [hospital/desktop-app/session-health.js](desktop-app/session-health.js) **เป็นสำเนาไบต์ต่อไบต์** ของ [public/scripts/scp-session.js](../public/scripts/scp-session.js) ที่ [main.js](desktop-app/main.js) ฉีดเข้าไปในหน้าต่างแอป แก้ฝั่งเว็บไปแล้วแต่ฝั่งแอปยังเป็น PNG อยู่ — **เจ้าหน้าที่ที่ใช้แอปจะยังเจอปัญหาเดิมทั้งที่คิดว่าแก้แล้ว**

ซ้ำร้าย `main.js` ยังเป็น**ที่ที่สาม**ที่ตั้งค่าภาพ และตั้งไม่ตรงกับอีกสองที่ (`quality=90` + `ImageType=2` ซึ่งคือ PNG และ PNG ไม่สนใจค่า quality อยู่แล้ว) ตอนนี้ปรับให้ทั้งสามที่ตรงกันหมดแล้ว **พร้อมเทสต์ที่จะ fail ถ้าสองไฟล์นี้เพี้ยนจากกันอีก**

> **ต้อง build แอปใหม่** การแก้นี้จะยังไม่ถึงเครื่องที่ติดตั้งแอปไว้แล้ว จนกว่าจะ `cd hospital/desktop-app && npm run package` แล้วบีบ zip แจกใหม่ (ดู [DESKTOP-APP.md](DESKTOP-APP.md))

ตอนนี้ "คมชัด" = WEBP คุณภาพ **100** เต็มความละเอียด ซึ่งกินแบนด์วิดท์สูงสุด ถ้าจะประหยัดกว่านี้ ขั้นถัดไปคือ **90** (ตัวเลือกที่หน้าเว็บมีคือ 100, 90, 80, 70, … ไม่มี 85)

> ระวัง: โปรไฟล์ "คมชัด" จะถูกสั่งทุกครั้งที่ได้ภาพแรก ฉะนั้นค่าที่ตั้งในหน้า Settings ของ MeshCentral เองจะถูกทับตอนเริ่มเซสชัน (เปลี่ยนกลางเซสชันยังได้อยู่) ถ้าจะเปลี่ยนค่าถาวร ให้แก้ที่บันไดใน scp-session.js ไม่ใช่ที่หน้า Settings

## 5. บทเรียนหน้างาน — บันทึกไว้กันพลาดซ้ำ

### 5.1 Mesh Agent ไม่ขึ้นใน Safe Mode แม้จะลงทะเบียนไว้แล้ว

ทดลองจริงกับ ARI พยาบาล: เพิ่มคีย์ `SafeBoot\Network\Mesh Agent = "Service"` ยืนยันคีย์ติดจริงแล้ว รีบูตเข้า Safe Mode **ผลคือ Agent ไม่ต่อกลับมาเลยเกิน 100 นาที** → **อย่าวางแผนทำงานรีโมตใน Safe Mode กับเครื่องโรงพยาบาล**

### 5.2 Task Scheduler ก็ไม่ทำงานใน Safe Mode

`SafeBoot\Network` ไม่มีคีย์ `Schedule` ตามค่าเริ่มต้น → แผนสำรอง "ตั้ง scheduled task ให้ถอย safeboot อัตโนมัติ" ใช้ไม่ได้

### 5.3 `service:restart` รายงานว่าสำเร็จทั้งที่ไม่ได้รีสตาร์ต

`npm run service:restart` พิมพ์ stopped/started ทุกครั้ง แต่ process เก่าอาจค้างเป็น orphan ครองพอร์ต 8443 ตัวใหม่จองพอร์ตไม่ได้แล้วตาย เหลือ orphan เสิร์ฟโค้ดเก่า → **การแก้ไฟล์ฝั่งเซิร์ฟเวอร์ไม่มีผลโดยไม่มีสัญญาณเตือน**

**วิธี deploy ที่เชื่อถือได้ (orphan-aware):**
1. `npm run service:stop`
2. ตรวจว่า process เก่าตายจริง + พอร์ต 8443 ว่าง (ถ้ายังค้าง ฆ่าลูกก่อนแม่)
3. `npm run service:start`
4. ยืนยัน PID **เปลี่ยนจริง** และ HTTPS 8443 ตอบ
